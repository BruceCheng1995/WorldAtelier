# 协作创作验收计划

日期：2026-09-07。状态：待实现接口、待执行。此计划不修改产品代码，也不把协议设计称为实际能力。

## 1. 本轮目标与验收顺序

从空游戏或用户明确选择的模板出发，A 与 B 使用独立账号在同一分支、同一文档编辑；共享开发者相机位置和真实名字；长期会话驱动真实 Codex 执行，状态与工具、候选、验证及现场应用关联；同一网页视口实际 Godot Play；A 个人检查时 B 继续游玩。最后完成珊瑚树交互、空间锚点脚底礼花和 Blender 修改星门顶部地球仪三个指定任务。

| 阶段 | 操作与硬性判断 | 负责证据 |
| --- | --- | --- |
| 0 | 固定实现契约、源码哈希和隔离目录，记录所有缺口 | 独立只读审查，不执行任务 |
| 1 | A/B 真实 WS 同文档编辑、冲突、重连和服务重启后保留；全预制件可独立编辑 | 独立 API/WS；主集成者双浏览器补图形 |
| 2 | 相机位置/名字、草稿预览、不同分支/文档/身份隔离；长期会话与附件 | 独立协议、持久化；主集成者 CUA |
| 3 | 真实 Agent thread/turn/tool、候选、验证和应用；取消、输入/审批及续聊 | 实际执行器记录，不注入假事件 |
| 4 | 同版本真实 Godot Web Play、A 检查 B 继续、恢复与坏候选退路 | 真实 authority 与 Godot 输入；双浏览器 CUA |
| 5 | 三个指定任务在上述完整路径中实施并游玩验证 | 每个任务独立因果链及实际画面 |
| 6 | 固定分支合并、权限撤销、重启、并发 Agent/手动编辑回归 | 新代码上的针对性故障测试 |

某阶段缺接口或失败必须记录具体原因；不能靠跳过测试、预置任务结果或继续扩大其他功能宣布阶段通过。

## 2. 环境、身份与执行限制

- 服务由测试子进程启动，端口 48921，数据根为新临时目录。重启测试保留同一测试数据；另一个全新目录仅用于独立场景。记录 PID、父进程、实际启动参数和退出状态，隐藏 token/host key。
- A 为项目拥有者，B 为编辑者，V 为只读成员，X 为非成员；另建项目 Q。用户都经实际认证 API 创建，没有直接写数据库植入身份或“通过”数据。
- A/B 各有独立 WS/socket/client_id。多个浏览器窗口是否属于同一人必须另外记录，不能把两个页面假定成两个协作者。
- 主干与分支复用相同 resource_id/node_id 以主动覆盖作用域错误；同分支再开第二场景和预制件定义。
- API 探针可以发送合法编辑事务和普通玩家输入；不实现伪 `/host`，不伪造 Godot loaded/applied/ready，不写玩家位置、奖励、completed 或数据库结果。
- 图形统一由主集成者 CUA；测试者不操作浏览器。headless 只证明实际加载、模拟或输入代码路径，不证明 GPU、手感、浏览器焦点和连续画面。
- 失败注入只能影响拥有的测试进程/数据。通过 kill/restart 或真实损坏候选触发，不修改产品为“必过”，不依赖用户世界。
- 真实 Agent 仅在接口、工作区、作用域和证据管道就绪后执行。隔离候选不得直接改正常世界或当前应用运行目录。

## 3. 不混用的证据等级

| 记录 | 能证明 | 不能单独证明 |
| --- | --- | --- |
| 认证与事务响应 | 服务接收、拒绝或持久化的操作身份 | 同伴已显示、玩法已更新 |
| WS 文档增量/基线 | 指定作用域内连续同步 | GPU 已画出新模型 |
| Codex thread/turn/item/tool 事件 | 执行器确实收到请求和执行的动作 | 产物有效、目标已完成 |
| 工具产物与 ChangeSet | 对应源文件/资产实际改变 | 已通过测试或已应用 |
| 真实构建/验证结果 | 固定候选在所测范围有效 | 任意代码安全、所有目标都满足 |
| Godot applied 与权威状态 | 指定世界实际使用候选 | 两端 GPU 均已显示 |
| 浏览器输入、画面和权威结果 | 被实际操作的界面与玩法结果 | 未执行的其他 Agent 能力或无限覆盖范围 |

最终汇总逐项标注 `not_run / running / passed / failed / blocked` 与实际证据路径；`blocked` 是具体缺口而不是通过。混合 API/GPU 项在所有必要证据齐备前不标 passed。保留初始失败、修复后复验和工具日志中的实际错误。

## 4. 数据与并发验收重点

### 文档、预制件和分支

1. 创建空项目、新场景、未摆放的美术/逻辑预制件。目录是持久化定义而非场景中对象的投影。重开后所有资源和版本仍存在，预览地面/相机不进入定义。
2. A/B 同基线并发改不同对象：两笔成功、最终文档包含两者、顺序明确；同一对象整组 TRS 冲突，不自动拼成未经确认的组合。旋转/非均匀缩放/非零 Y 保留完整值。
3. 同 transaction_id 同 payload 并发、断线、重启后重发只产生一次变更；不同 payload 明确拒绝。提交成功但响应丢失可查原操作，不能重复创建对象。
4. 混合 create/reparent/transform/delete 中后半非法时整笔不生效。多资源 ChangeSet 的依赖验证或 head 比较失败时没有半套 manifest 可见。
5. baseline S 与首次订阅衔接期间提交编辑，所有客户端最终收到连续状态。断线日志不足时要求完整基线；不跳过缺口。`document_sequence`、`world_sequence`、Agent 事件游标分别记录。
6. 切分支/文档后旧订阅晚包、预览和 ACK 不污染当前对象，即使两个资源/node ID 相同。undo 是有前置条件的逆事务，不能用本地历史覆盖同伴新值。
7. 多级祖先变换、重挂父级和嵌套 prefab 两个实例同内部节点准确寻址。祖父移动但父局部版本不变，旧世界坐标提交仍被拒绝或显式重基。
8. 分支固定 base/source/target 后合并；下载或预览期间 target 变化重新比较。多次合并不丢改、不重复应用、不把在线世界/离线背包合进文档。

### 相机、名字与临时编辑状态

1. 两位真实用户移动编辑相机，另一端看到对应位置/朝向/名字；包中 user_id/name 从认证身份派生。发送伪 actor/name 不冒充他人。
2. Presence 固定 project/branch/resource/client/订阅代次，含单调更新号和过期时间。切 tab、切分支、断线后旧相机与拖动提示离开；同用户多个窗口独立处理。
3. 相机姿态不会写 SceneDocument/source revision，不成为玩家坐标，不驱动别人的视口。编辑预览的短租约只用于反馈；失焦/断线/取消恢复已提交 TRS。
4. 对象青色选中、橙黄维护圈和施工标志由真实 actor/run 状态驱动。多个目标分别保留，结束一个不清掉其他运行；失败/取消停止运行动画并保留可解释状态。只有本人被选中而无真实运行时不伪造“Agent 正在开发”。

### 会话、附件与权限

1. 每分支每用户两个长期会话，消息/工具记录分页恢复。退出登录、浏览器重开和服务器重启后可以续聊；登录 token 与 CreatorSession 生命周期独立。
2. 会话私有/共享权限在列表、直接 ID、消息、附件、工具事件、幂等回放和 WS 都检查。公共协作/presence/维护圈只放已授权公共字段，不能借项目成员资格泄露私人正文。
3. 对象或空锚点附件固定项目、分支、资源/节点版本、完整实例路径、局部 TRS、世界坐标、坐标约定、祖先指纹和观察相机。若来自试玩，固定 world/release/epoch/sequence/state_hash。
4. 附加后再移动、改名、删除锚点或切分支，已发送附件原样保留。Agent 读取的是原始观察并能取得当前差异；不能偷换成当前选中对象。
5. 撤销或降低权限时，旧 socket、排队事务、下载、Agent late commit、私有事件订阅和 operation 回放都重新校验。发送请求的 actor、分支或 lease 字段不能代替服务端授权。

## 5. 真实 Agent 的完整接入门槛

需要保存并能交叉关联：`creator_session_id → goal_id/cycle_id → run_id/lease_generation → executor_thread_id/turn_id → item/tool_call_id → change_set_id → verification_id → release/world receipt`。

- 先确认实际执行器和可用工具版本、工作目录、身份/限制；消息先持久化再触发。发送成功文本或固定回复不算运行证据。
- 保留真实增量输出、工具开始/结束、退出码、必要的代码差异/产物哈希和错误；中央服务重启后与执行器核对。断流恢复从游标接续，不能盲目再执行同一次 Blender 或写入。
- 场景工具和手动编辑共用事务。每次 Agent 写入重核基线、分支、有效周期/租约与取消状态。用户切分支不会使后台任务改写新分支。
- UI 支持实际审批/输入请求及回复路由；允许/拒绝只能回到对应 run/turn/item。若本机配置没有出现某类真实请求，该类记未执行，不能编造事件填满验收。
- 取消在排队、工具执行、候选验证三个阶段分别检查。旧 worker 晚提交被围栏拒绝；已提交变更不能无条件倒回，撤销仍需比较最新版本。
- 同一会话后续对话、失败后的修改/重试保持真实上下文。一次 turn 完成不自动终结长期 session；错误不能被一条完成文本吞掉。
- 对象状态从真实运行与变更投影。改名、其他人改同对象、另一个目标完成、构建通过均不能自动把“实现交互”目标标完成。验证通过、可应用、已应用和目标验收分别保存。
- 工具缺失/审批未决/进程退出/候选错误真实展示，保留旧可用内容。三个演示任务不会证明任意工具、任意代码或通用 Godot HMR 安全。

## 6. 实际 Play 与个人检查

1. 当前视口运行当前场景对应的真实 Godot Web；保存 source/resource/runtime/release，核对真实 authority PID 和 epoch。A/B 普通输入控制各自角色，完整三维位置、碰撞与交互有实质结果。
2. 构建、下载或解析失败保留原编辑上下文，明确目标未就绪；不能静默播放旧版或将模型预览当游戏。
3. A 移动中暂停检查：零输入确认，authority 和 B 继续 tick/移动/交互。A 冻结的资源、tick 和状态不变，但相机、拾取与文档编辑仍可用。不得调用 freeze/sleep、另建 world 或停网络替代。
4. B 修改/删除对象后，A 的冻结观察不漂移；文档版本变化另行提示。A 编辑同字段需冲突处理，不把模拟姿态自动保存为初始布局。网络状态缓存有明确上限。
5. A 返回实时对齐当前发行、epoch、控制代次和连续基线，清按键/插值。检查期死亡、升级、重启、角色控制转移采用真实当前结果；失败保留可解释检查状态，未就绪不给输入。
6. 兼容候选应用保留进度，坏候选保留旧内容；不兼容程序交接允许新运行实例但明确记录 PID/epoch，不能称同进程热更。

## 7. 三个最终真实任务

| 任务 | 执行与版本证据 | 必须实际体验的结果 |
| --- | --- | --- |
| 珊瑚树角色交互 | 指定场景/实例附件进入真实 session；真实代码或组件工具产物；验证与应用对应同 ChangeSet | A/B 角色通过普通输入到达并触发新交互；距离/条件不满足时不误触发；记录权威事件/状态与 Web 画面 |
| 空间锚点脚底触发礼花 | 固定准确锚点、坐标/祖先指纹；真实 Agent 根据附件创建组件/触发体；编译/碰撞验证和发行回执 | 角色脚底实际进入目标区域触发礼花，离开不误触发；不能用倒计时、页面按钮或直接写 event 替代。观察是否重复触发遵循 Agent 提交的明确规则 |
| Blender 修改星门顶部地球仪 | 真实 Codex 工具调用启动 Blender；保留工具命令、日志、版本、源模型/产物哈希及导出记录；实际上传和绑定对应对象 | 编辑预览与实际 Web Play 看见变化，目标地球仪准确，其他星门结构按变更范围保留；坏导出不替换旧模型。没有原 .blend 时明确从实际 GLB 导入修改，不伪造来源 |

三个任务各自记录开始基线和最终验收。保留新增内容的创建过程，不以旧战役对象任务或预先放好结果替代。公共开发状态须能追到真实任务，但私人会话正文不自动广播给 B。

## 8. 最小证据索引

每轮 `run.json` 记录代码 HEAD 与 dirty 源文件 SHA-256、Node/Godot/浏览器/Codex/Blender 实际版本、启动模式、测试地址、隔离目录和 PID。日志去除 token、host key 和未经授权的私人正文。

按用例保存必要身份：project/user/client，branch/resource/node/instance_path，transaction 与基线/结果 revision，document sequence/subscription generation，resource manifest/asset/code hashes，session/message/goal/cycle/run/lease/thread/turn/tool，verification/change/release/runtime，world/epoch/sequence/control generation，inspection baseline。

原始 HTTP/WS、执行器事件、authority 日志、产物与截图通过这些身份连接。时间用于对齐，不用墙钟相近代替因果关联。首次失败保留；重跑产生新 run ID，不覆写失败为成功。
