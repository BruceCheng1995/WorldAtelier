# 随部署提供的默认工程

2026-10-30。默认工程用于让新部署的访问者直接查看已完成的创作成果。它们出现在原游戏库中，使用原工作台、原生源稿、预制件编辑器和统一 Godot Play 入口。

## 首批内容

本次固定当前全部 9 个未归档工程的 11 个分支：小小梦魇、俄罗斯方块、坦克大战、小巷漫步、塔防游戏（2 分支）、TPS、植物大战僵尸（2 分支）、兽人必须死、贪吃蛇。已归档工程不分发。

`content/default-projects/catalog.json` 固定每个分支的完整 `source_identity`、源文件与引擎查询索引哈希、封面引用。`objects/` 保存按原始字节哈希去重的 gzip 对象；大对象按不超过 16 MiB 分片。首批压缩大小约 216 MiB，主要为小巷漫步的大型场景资产。完整原生文件（包括未展示或未知文件）保留，不用查询索引反向生成场景。

查询索引随其准确源身份分发，用来避免首次安装前就运行全部作者工程；它仍是引擎派生数据。安装后的中央原生归档和版本是内容权威，后续编辑继续通过原事务维护索引。分发包不是运行中的另一份可编辑场景。

只分发源稿与封面，不复制用户、密码、登录、成员关系、聊天、附件、执行历史、数据库、运行存档、构建包或发布指针。新库的分支各有一个固定起始版本，不宣称保留原创作历史或原分支合并祖先。

## 部署与体验

按 README 安装 Node.js、Godot 4.6 及匹配 Web 模板，执行 `npm install`、`npm run build:preview`、`npm start`。48910 服务首次启动在监听前安装默认工程，注册后直接显示现成内容。无需 Codex 登录即可查看和试玩；仅在使用 Agent 创作时需要配置执行器。当前支持范围仍以 README 的本机/macOS 环境为准，这次不新增云托管或跨平台运行后端。

所有已注册用户对默认工程获得派生的 `viewer` 权限，可看场景、预制件与游戏知识，并按固定源版本构建独立 Play。首次场景预览和 Play 可能需要等待 Godot 构建，后续使用既有缓存。普通项目的公共 `player` 仍只运行显式发布的固定游戏构建；安装和构建默认工程均不创建公开发行或共享世界。

默认工程不附带共享账号或密码，不授予公共编辑、Agent 执行或原始源码下载权限。新安装的默认工程没有人类拥有者，因此不显示无法审批的编辑申请。首个注册账号仍可创建自己的游戏；不会因为种入默认工程而失去首次创作资格。默认工程中派生的查看权限不开放私人或成员共享会话。

`WORLD_ATELIER_PUBLIC_PLAY=0` 与项目 `public_play=false` 仍会关闭非成员访问。账号停用、项目归档继续生效。

## 安装、保留与更新

- 正式 48910 默认安装；`WORLD_ATELIER_DEFAULT_PROJECTS=0` 可关闭后续安装，不删除现有内容。隔离测试端口默认不装，需显式 `WORLD_ATELIER_DEFAULT_PROJECTS=1`。
- 每个工程使用稳定 ID。重启、重复部署不写新版本、不重置归档或权限、不覆盖用户修改。
- 原工作区已有相同 ID、全部分支源身份与分发包一致时，只添加默认工程标记，使注册访问者可查看源场景并试玩；原成员、源 head、历史和会话均保留。相同 ID 但源身份不匹配时保留原工程并报告冲突，不导入重复副本。
- 导入逐文件解压并验证哈希、大小和可移植路径；同一工程的全部分支、封面与版本在一个 SQLite 事务中登记。中途失败不会显示半套工程。
- 内容包更新只为缺失的工程提供新安装输入，不自动升级已安装工程；部署中的创作状态由其中央源稿管理。

维护者从自己的创作数据目录显式导出到一个新的空目录，审查后替换仓库里的分发包：

```sh
node tools/export-default-projects.mjs \
  --data=.local/model-preview/creation \
  --out=.local/default-projects-next
```

默认导出全部未归档工程和现有分支；可用 `--projects=工程ID,工程ID` 限定。导出使用只读 SQLite 一致快照，逐个固定源读取，不修改正式工程。不要把本机 `.local` 数据库或构建目录加入 Git。
