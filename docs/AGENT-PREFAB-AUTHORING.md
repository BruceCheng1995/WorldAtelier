# Agent 预制件创作约定

2026-09-17。保持现有 `creation-native-1` 原生源权威、事务、持续会话与自选测试。

本次问题表现为塔防工程只有一个 512 节点场景，没有独立预制件；炮塔、敌人和障碍物由模型工厂临时创建。现有上下文讲解了 PackedScene 继承、提交与能力预览，但没有要求识别可独立编辑的玩法对象，也没有明确要求恢复共享工程结构知识。未发现中央记忆丢失的证据。

`services/creation/agent-prefab-policy.mjs` 统一维护简短提醒和完整准则：

- 新建/恢复线程接收简短提醒；每轮执行再次提供，覆盖已经加载的长期线程。
- 原生 `WORLD-API.md` 与 `AGENTS.md` 提供完整拆分原则。语义指南要求读取本轮知识索引，按需读取完整条目并与当前源核对。
- 重复生成、存在变体、需要独立编辑/调参的对象使用实际 PackedScene；原生节点、模型、参数与行为可编辑，并被场景或运行时真实实例化。
- 场景负责布局与关卡调度；不按每个叶节点拆文件，不因微小参数编辑自动全工程重构，不用空壳场景、脚本工厂或目录卡片替代预制件。
- 保留原生未知属性、稳定身份、实例差异和本地未提交内容。结构调整后，将职责、路径、调参点与真实消费者记入版本化共享知识，不复制私人会话。
- 旧 flat/H2 工程继续遵循自己的版本契约，不因此迁移。能力预览按需制作，不增加自动测试、审批或发布门禁。

`tests/creation/agent-prefab-policy.test.mjs` 使用实际 adapter/manager 投影链路和临时 SQLite，并明确使用 FAKE 外部 RPC；验证新建、恢复、续写、知识索引和旧工作保留。它证明上下文传递，不作为真实模型遵循提示或游戏玩法的证据。

本次塔防工程按职责拆成 18 个真实定义：3 类炮塔、4 类感染者、3 类障碍、3 类弹体、1 个碎片特效、松树/入口/避难所和 HUD。类型共用行为脚本；关卡保留布局，游戏脚本负责经济、波次、输入和胜负。松树和障碍由场景实例复用，炮塔、感染者、弹体与特效由运行时实例化。HUD 原生按钮可独立调整，卡片图文跟随按钮变换。

静态审查与固定中央基线比对，保留原有 512 个节点身份及主要视觉属性。规范入口实际检查覆盖 18 个预制件独立加载、真实实例来源、建造/升级/出售、清障、减速/范围伤害、12 波通关、失败和多次重开，共 93 项；后台嵌入渲染核对场景及战斗画面，音频使用 Dummy。检查也发现并修复了临时节点自动名称与既有序列化名称冲突的问题：在加入树前命名，动态重复实例使用可读唯一名称。

提示词相关回归合计 43 项通过。源稿及共享结构知识通过带当前 head/文件哈希约束的原生事务保存；工程副本、测试输出和数据库备份留在忽略目录内。原始会话工作目录保留，源稿保存不等于公开发布。

后续实际 Web 打开暴露了此前原生运行检查没有覆盖的兼容缺陷：`renderExplorer` 调用共享的 `fullAddressKey`，却沿用了 H2 的短 ID 校验，合法的原生节点身份（例如 `prefab-tower-machine_gun/Head/SingleBarrel`）触发 `invalid_address`，使整页进入错误状态。共享只读键现按原生协议保留不透明身份（1–1024 字符、无控制字符、实例链最多 128 层），项目/分支/资源作用域及 H2 写操作仍使用原校验。原生源文件和节点 ID 无需修改。

修复后检查当前中央工程 19 个资源、792 个对象地址，包含 225 个带斜杠的节点身份；地址键无异常或重复。新增原生投影、边界与 H2 写协议隔离回归，连同原有测试共 11 项通过。用户实际 Chrome 原页面刷新后已显示「塔防游戏 / main」、18 个预制件、628 个场景对象及加载完成的 Godot 视口；这是本次 Web 入口恢复的直接证据。
