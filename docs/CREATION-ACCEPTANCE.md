## 3. 个人暂停专项

以下均要求 A/B 两个真实客户端和权威记录；单界面按钮切换不能证明。

1. A 在移动时进入检查：零输入被确认，角色不继续漂移，检查键只控制相机；B 继续移动和交互，权威 tick 增长。没有调用 world freeze/sleep 或另建 world。
2. A 的检查快照固定完整的发行、资产、对象和序号。B 变更模型/位置后，A 收到新编辑提示，但检查画面不会悄悄混入新模型或新位置。
3. 检查期间网络持续处理，缓存有界；超过测试窗口不积压全部帧或无限增长内存。相机可看到冻结物体的其他角度，不能以静态截图代替。
4. B 删除/改名 A 所检查对象：A 仍能查看历史对象，但不能以名称、数组下标或相邻对象误绑定；提交版本冲突可以解决。
5. B 修改相同变换后 A 拖动：明确重基或冲突，不能整份回写暂停时场景。A 对动态物体做批注不能自动改其初始布局。
6. A 检查期间角色死亡/世界升级/重启：返回实时采用最新状态、代次及发行；不复活到旧血量，不重放旧按键。不兼容版本交接不能称同进程热重载。
7. 恢复中断网/资源损坏：保留可解释的检查状态，继续重试；未同步前不给玩法控制权，不报告恢复成功。
8. 检查期间切分支/被撤销权限/控制被转移：旧引用不漂移，不向新分支误写，也不能越过权限继续提交。

## 4. 实例和版本专项

至少覆盖多个同预制件实例的相同内部节点被准确区分、祖父移动而父局部字段不变时拒绝旧世界坐标提交、多级父子变换、非零Y、旋转/非均匀缩放、预制件嵌套、同一预制件多个实例、实例覆盖升级、内部节点删除、资源循环引用拒绝、未知组件拒绝、非法模型拒绝，以及 undo 不覆盖别人修改。

还需注入四类一致性/可见性条件：切分支后同 resource_id 的旧订阅晚包不能污染新文档；baseline S 与订阅之间发生修改不能丢操作；取消/重试后旧 Agent worker 的晚提交被运行代次围栏拒绝；私人目标正文/附件/工具参数不能从协作 tab、施工状态或活动流泄露。多资源 ChangeSet 验证失败或并发 head 改变时，不得公开半套依赖。

验收内容必须在创建旅程中实际产生，不能只用已有战役对象。美术规模不替代交互正确性，测试数量不替代用户核心体验。
