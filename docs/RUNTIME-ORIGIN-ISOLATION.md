# 作者游戏与创作账号隔离

工作台仍由同一个 48910 服务提供。作者游戏运行在独立来源；中央源稿、权限、固定构建和发行规则保持同一套服务记录。

## 来源与授权

本机工作台 `http://127.0.0.1:48910` 使用 `http://wa-runtime.localhost:48910` 运行游戏。浏览器把该本机来源视为 secure context，保留 Godot Web 所需能力。局域网使用同服务 IPv4 对应的 IPv4-mapped IPv6 地址，沿用单线程局域网 HTTP 的无声边界；旧固定构建缺少该地址适配时明确拒绝，要求本机运行或创作者显式产生兼容新版本，不改写归档字节。

运行 Host 在创作 API 路由之前分流，不提供创作、管理或创作 WebSocket。固定构建的读取使用短期、可续期的能力票据；每次续期重新检查登录与访问权。运行地址没有创作 Cookie、登录令牌或通用 HTTP 代理。直接打开旧的作者发行 HTML 也不能恢复同源作者代码执行。可信的静态模型编辑器预览另有去脚本规则，不代替实际游戏隔离。

嵌入 Play、独立新页面、预制件测试和原生共享显示端使用同一访问边界。固定运行外壳保留原构建文件；外壳和工作台之间核对实际窗口、来源、启动 nonce、构建/源与场景身份。只允许约定的状态、检查、输入、上下文和截图消息。新页打开前清除复制的创作 sessionStorage，并断开 opener。

截图通过限定请求与回传，不从创作页面跨源读取游戏 canvas。现代固定工程在渲染结束时回报同 tick 观察；旧构建使用明确不保证同帧对象投影的兼容截图。作者消息、日志、节点名和截图是待分析数据，不能授予创作写权限。

## 存档

嵌入 Play 继续使用内存存档，每次明确重开回到初始状态。独立新页使用固定的游戏存档域。

可信工作台仅扫描对应旧 Godot `user://` 域。发现旧存档时，用户可迁移、导出或明确从新存档开始；读取失败也要可见，不按「无存档」静默处理。迁移在运行来源的一次受限事务内进行，校验路径和字节预算，不覆盖已有存档，保留旧来源原件。它不是通用 IndexedDB 代理。

本轮多个游戏共用运行 origin，因此这里只确认「作者游戏与创作账号隔离」。不同游戏之间尚无独立的浏览器存储安全边界，不能把不同路径或数据库名描述成跨游戏隔离。

## 验证边界

真实浏览器检查需分别覆盖 Cookie/存储/DOM、创作及管理写请求拒绝、消息身份、实际 WASM/PCK 加载、截图、独立存档与局域网入口。薄页面证明来源隔离不等于实际 Godot 游戏可运行；构建完成也不等于玩法通过。独立验收清单见 [next-wave-acceptance.md](../tests/creation/next-wave-acceptance.md)。
