## 用户代表色 v1

`collaboration-client.js` 的 `userColor(user)` 用中央服务已持久保存的随机用户 UUID 生成固定色相、饱和度与亮度。随机种子归属账号，不取用户名、注册顺序、窗口 ID、会话或浏览器存储，因此同一用户跨刷新、重连、分支与浏览器保持同色。同名不同账号仍有独立种子；颜色不是身份认证或全局唯一标识。

这是从持久随机身份派生的显示协议，没有每次刷新重新抽色，也没有在数据库中增加第二份可变颜色。当前工作台覆盖旧版四种循环色显示；`creator_user.color` 的历史值保持原样。未来其他客户端如要显示同一身份色，应采用相同 v1 算法。

`previewPeers` 在把用户 ID 换成窗口标记 ID **之前** 求色，同时保留 `user_id`。Godot 现有相机覆盖层使用该 RGB 绘制锥体和姓名；不改相机位置、网络权限、个人检查或 Play 的显示规则。亮度范围经过小字对比度检查。2026-09-09：机器人 Agent 使用最初创建者 `owner_user_id` 的同一 RGB 代表色，保留机器人图标。查看者、会话公开范围与运行变化不改变颜色。顶部将同一创建者的活跃 Agent 归为一个头像，多个时显示数字数量角标及轻微堆叠；需要回复的会话优先代表该组。展开列表仍保留每个会话，未知创建者显示中性色。

## Agent 头像动效（2026-09-08）

顶部协作者、Agent 下拉列表、会话切换列表和聊天标题使用相同状态提示，保留创建者代表色：

| 状态 | 提示 |
| --- | --- |
| 启动 / 工作中 | 3.6 秒慢呼吸，机器人位移不超过 0.7 px、缩放不超过 3.5% |
| 当前账号有真实待答请求 | 每 6 秒短暂轻摆，琥珀色「?」角标；优先放在头像队列前面 |
| 其他人的请求 / 停止中 / 待核对 | 静态状态角标，不催当前用户回答 |
| 执行失败 | 静态「!」角标 |
| 本次观察到执行结束 | 1.6 秒淡出提示，1.8 秒后退出临时展示；不代表自动检查或发布通过 |
| 历史已结束 / 未启动 / 状态不可用 | 保持静止 |

请求提示要求可答复的真实请求类型、当前运行的准确 thread/turn 与会话所有者相符；过期、已答复、未知请求类型不触发个人回复提示。选中需要回复的会话后定位已有请求组件，不自动答复或授权。断线停止状态动效，读取不完整时显示待刷新。

同态渲染复用头像节点，避免聊天流式更新反复重启动画。完成提示不因普通重绘续期；切换账号、分支或重新进入时，历史完成不重播。`prefers-reduced-motion: reduce` 关闭头像、SVG 和伪元素动画，保留角标和文字。没有增加声音、弹窗或新的后台服务。

本次独立状态/DOM 模拟测试及相关回归 77/77 通过，记录在 `.local/agent-avatar-verification/final-tests.log`。原 48910 浏览器实测了历史会话静止、下拉与标题状态；工作、请求和结束过渡由明确的模拟传输与 DOM 测试覆盖，本轮没有为了测试而发起真实 Agent 执行或请求。
