# 本机客户端与共享世界接续

本轮支持现有本机 Godot 4.6 环境。它使用中央共享世界的固定原生显示工程，不是新的离线世界，也不改变原分支的源稿。完整多平台出包仍不在本轮范围内。

## 用户入口

原工作台顶部「本机与离线工作区」→「本机接续共享世界」提供下载工具和带当前项目、分支、场景的命令。共享世界必须已经由创作者明确发布；工具不会自动发布当前编辑内容。旧固定共享版本没有接续协议时，保留现有 Web 运行，明确提示创作者更新共享版本。

本机工程下载沿用拥有者/编辑者权限；运行中的游戏票据只提供相应共享世界的玩法能力。公开试玩账号的 Web 权限不会自动变成工程导出权限。

下载的是单文件 Node.js 工具。`prepare` 只准备固定工程；`connect` 准备完成后接续当前账号的角色。终端 `--login=账号` 隐藏密码输入；非交互登录可用 `WORLD_ATELIER_TOKEN`。创作令牌不写入工程，也不传给 Godot 进程。实际命令以工作台生成内容为准。

每次准备先获取固定清单与工具链身份，按 SHA-256 复用已下载文件。缓存工程不直接运行；每次执行复制到独立 `executions/<id>/project`，先用 headless / Dummy 导入资源，再启动匹配的 Godot。清单外文件、符号链接和已变缓存明确拒绝并保留原件；新旧进程不共用导入缓存。游戏进程仅得到单世界、短期、可撤销的接续票据。

正常用户启动保留原游戏的音频与操作。无人值守测试使用 `--headless --timeout=秒数`，不会打开窗口或播放声音。

## 控制权交接

1. 新客户端实际加载固定工程，应用准备基线并回报它的世界、源版本、构建、场景代次和状态哈希。
2. 服务端封住旧输入，等真实 Godot 权威确认清零输入；原画面暂时保留。
3. 新客户端实际应用最后基线。服务端发出候选控制代次，此时仍不接受其玩法输入。
4. 新客户端确认控制消息已应用后，服务端持久提交新的控制代次并结束旧控制。客户端收到 `control_confirmed` 才报告可操作。

下载、准备或提交前断连会保留旧控制或请求旧端应用新基线后恢复；只有旧端实际确认才记录恢复成功。旧票据、旧准备意图和旧输入不能在新控制结束后重新生效。

服务端提交后最后确认丢失属于「已提交后断连」。启动器查询持久交接回执并区分此状态，不说成「未接续」。在控制代次仍属于该次提交时自动重新解析和接续，最多尝试三次；后续其他操作已经接管则停止自动恢复。服务不可达时明确显示结果尚未查明。

固定内容或世界更新可能启动新进程，直到新端确认控制才结束旧进程。这里承诺状态与控制连续性，不承诺同一进程、零等待、任意协程或物理状态搬运。共享权威只保留已声明的状态；离线内容同步和独立存档不会覆盖它。

## 验证与数据

真实基线、控制确认、玩法输入与恢复需要实际 Godot 验证。文件下载完成、进程启动或退出码为零都不代表接续成功。当前独立验收清单见 [next-wave-acceptance.md](../tests/creation/next-wave-acceptance.md)，最终结果以本轮报告为准。

工程、导入日志和运行记录留在用户选择的本机目录；固定缓存与执行副本分开。数据库保存工作区、票据哈希及交接回执，登录撤销或访问权变化会重新校验。已经下载的字节不能远程撤回。
