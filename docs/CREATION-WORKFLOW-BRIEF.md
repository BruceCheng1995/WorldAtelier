# 产品方向纠偏：协作世界创作

日期：2026-09-07。此文记录用户最新要求，优先于此前以发行与战役为中心的产品完成度判断。以前的测试作为底层能力证据保留，不能证明新的核心体验已完成。

## 用户明确的核心

多人在同一个世界里编辑场景；可看到全部预制件，打开独立场景编辑预制件。产品主线为：

1. 创建游戏。
2. 开发者通过对话创建场景。
3. 通过对话创建预制件：美术资产以及带逻辑的预制件。
4. 点击 Play 测试 Godot 原生可玩版本。
5. 在 Web 3D 预览视口修改布局、摆放预制件；手动和 Agent 使用同一份场景。

## 分支

协作者从当前状态树分出版本，不影响主干；可以手动合并回主干，也可以继续独立发展。在编辑工具里，主干和所有分支地位对等，都是可协作的游戏版本。提供多分支入口面板，不能只用发布页面中的一个下拉菜单表达分支。

## 场景和预制件编辑

Web 游戏可随时暂停，并让相机脱离角色自由漫游。视口点选对象后，右侧检查器聚焦对应对象。对象 tab 展示实际模型预览，支持导入模型、Agent 调用 Blender 生成；为未来 3D 生成服务留适配入口。不再提供规则 tab；保留协作 tab。

预制件是可复用定义，场景对象是实例，模型文件是资产。这三者必须分开建模。全部预制件目录和独立编辑场景是产品功能，不可由开发目录里生成的测试 .tscn 文件替代。

## Agent 与长期 Session

任务是 Agent 目标，可调用工具、修改代码、生成资产、测试并产出变更。每个分支、每个协作者都有一组长期存储的 session，体验类似项目下的会话列表。

点选对象做批注时，把对象信息添加到目标 session 的对话上下文。附件应固定所属游戏、分支、场景、对象/预制件 ID 和版本，不能随用户切分支或对象被改动而悄悄漂移。

批注支持精确空间坐标：用户创建空白对象，用操作柄移动到目标位置，再把位置作为附件加入上下文，让 Agent 能准确定位。空白对象是可操作的编辑锚点，不依赖预先存在的美术模型。

## 用户随后确认

- Play 默认“直接在当前网页视口运行 Godot Web 游戏”。
- 暂停“只冻结自己的检查视图，其他人继续玩”。

这两项是明确决定，不采用此前建议的本地窗口或共享暂停。完整产品设计见 [协作创作工作台](CREATION-WORKSPACE.md)，实施契约见 [协作创作协议](CREATION-PROTOCOL.md)。
