# 游戏首页与封面

入口仍是 `http://127.0.0.1:48910/creation-workspace.html`。实现位于原工作台的 `game-catalog.js` / `game-catalog.css`，通过 `workspace.js` 复用已认证的游戏目录、创建/加入流程与分支工作台入口。

- 首页展示当前成员可访问的全部游戏卡片，支持名称搜索、最近源稿修改 / 名称排序。游戏卡片提供分支快捷入口；选择游戏后展示该游戏全部分支，分支支持名称及 ID 搜索。
- 游戏详情展示头图、截图缩略图与大图浏览。游戏和分支各自支持最多 8 张 PNG / JPEG / WebP，单张最多 5 MB，最大边长 8192、总像素最多 3200 万。建议 16:9 横图。
- 默认从当前已经加载的 Godot 场景 / Play 视口自动截图：修改后安静 10 秒，再每 60 秒刷新。后台标签页、个人检查、拖动/未确认编辑、版本尚未同步和加载失败时不采集，保留上一张有效图。只读取游戏画布，不截取聊天与工作台 UI，不改变相机或暂停世界。
- 游戏自动头图来自 main，各分支自动截图独立；自动截图替换一个固定槽，旧的无引用图片文件会清理。截图保留实际来源分支、场景、源版本、运行客户端和编辑 / 试玩模式。无人打开视口时等待下一次真实画面，不用定时器伪造截图。
- 拥有者和编辑者可上传图片、设为头图、移除图片。任何手动覆盖都会关闭当前范围自动更新，设置中可以恢复；既有手动图片默认关闭自动。分支可单独设置封面，也可沿用游戏头图；新分支继承来源分支的截图集，后续独立修改。旧项目无图时展示明确的待上传状态。
- 成员数量来自项目成员列表，不宣称这些成员当前在线。分支的最近修改时间来自源版本，不代表构建通过或游戏已经应用。

## 保存与权限

`GET /creation-api/bootstrap` 的项目和分支包含 `presentation: {version, cover_id, images, auto_update, auto_image_id, last_auto_at}`。无图的旧记录读出空截图集与默认自动更新；已有图片且未声明自动设置的旧记录保留手动模式，不修改原源码/运行世界。

`PATCH /creation-api/projects/:p/presentation` 和 `PATCH /creation-api/projects/:p/branches/:b/presentation` 接受 `expected_version`，以及 `image: {data_url, name}`、`cover_id` 或 `remove_image_id`；单独提交 `auto_update` 可暂停 / 恢复自动更新，返回 `{presentation}`。比较版本失败返回 409；前端重新读取目录后才能按最新版本继续。删除当前头图会使用剩余第一张，删除全部则清空。

`POST /creation-api/projects/:p/branches/:b/auto-cover` 接受截图、分支/项目资料版本及真实画面上下文，核对源版本仍为当前 head 且资源为场景。只写入仍开启自动的范围；主干可同时更新游戏和分支，其他分支只更新自身。手动覆盖、旧版本和过期画面不会被自动写入冲掉。

元数据持久化到原创作数据库，图片按哈希存于创作数据目录的 `project-media/`。`GET /creation-api/projects/:p/media/:id` 每次核对成员权限与当前项目/分支引用。前端使用带 Bearer 的下载请求转换为 Blob URL，登出清理缓存，不把登录 token 写进图片 URL。此目录不进入 Git。

## 二级页面与 URL 路由（2026-09-08）

按用户纠正，游戏库与单个游戏分支页拆为两个页面，取消左右并排的主从布局。工作台仍使用原48910服务和原页面文件。

| 页面 | 地址片段 | 内容 |
| --- | --- | --- |
| 一级：游戏库 | `#/games` | 当前账号可访问的游戏大封面卡片、搜索排序、创建/加入、本机最近打开 |
| 二级：游戏详情 | `#/games/:projectId` | 该游戏头图、成员/权限、继续创作、分支卡片、创建来源与截图集 |
| 分支创作工作台 | `#/games/:projectId/branches/:branchId` | 原有真实文档、协作、Agent 会话和 Godot 视口 |

例如原入口 `http://127.0.0.1:48910/creation-workspace.html#/games`。使用 hash 路由，原服务无需增加路径回退或重启。游戏 ID 和分支 ID 分段编码；首页不根据本机上次选择自动打开某个游戏。

`workspace.js` 的 `navigateCatalog` / `applyCatalogRoute` 统一处理导航；其他进入分支的入口也委托给它。游戏卡片使用真实链接，支持复制地址或新标签打开。浏览器前进/后退与刷新依据 URL 恢复页面；未登录时先登录，成功后恢复原深链接。详情页“所有游戏”与顶部标志回游戏库，工作台顶部游戏名及分支菜单“全部分支”回当前游戏详情。

不存在、无权限或无法识别的地址显示明确错误与返回/重试入口，不悄悄切换到别的游戏。快速导航时，路由代次与原文档加载代次共同拒绝旧请求的晚结果。切换页面关闭旧模态框，原有草稿保存和世界退出逻辑继续复用。不会停止后台 Agent 任务。

选择与最近打开记录仅存本机 `localStorage`，键按用户 UUID 隔离。每次展示都与当前已授权 bootstrap 目录交集；不存在或无权限的目标不会成为入口。进入文档及会话读取成功后才记忆访问，加载失败不覆盖最近记录；此记录表示打开工作台，不表示 Godot 试玩通过。游戏创建默认空白场景，可显式选择模板。分支“从此分出”预选来源，创建对话框可更改来源并固定源版本，创建后进入新分支。

自动截图与手动覆盖规则保持原实现。游戏手动头图可与分支自动截图并存；媒体管理、图片下载授权、并发版本检查和恢复自动更新继续沿用。

## 手动拍摄与工程管理（2026-09-09）

游戏视口工具栏提供「拍摄封面」。编辑、独立试玩以及暂停观察均可拍摄已就绪的真实 Godot 画布；图片不包含工作台 UI。拍完显示固定照片，可取消、重新拍摄，或设为游戏封面、当前分支封面、两者。保存仅改变封面资料，不改变源稿、构建、发行或运行状态。对应范围关闭自动更新；用户可在原封面管理中恢复自动更新。曾手动保留的同像素自动图片转成独立手动照片，后续自动更新不移除它。

`POST /creation-api/projects/:p/branches/:b/manual-cover` 接受 `scope: project|branch|both`、两层 `expected_version / expected_project_version`、图片和实际画面来源（`source_revision / resource_id / runtime_build_id / mode / scene_generation`）。只允许 owner/editor；按选定范围原子比较媒体版本并设为头图。允许仍在游玩的本分支祖先固定源版本，保留原始版本记录；其他工程或分支独有的源版本拒绝。截图前后校验视口实例、文档、源版本、场景代次、导航和权限，采集过程中的切换会取消照片。预览形成后游戏可继续运行；照片仍绑定原始工程和分支，导航会关闭预览。旧保存回包只按版本递增合入本地，不覆盖更晚的封面。

工程拥有者可从游戏卡片或详情页重命名、归档。归档沿用后台已有 `archived_at` 语义：移出活动游戏库，关闭编辑和试玩访问，停止正在执行的 Agent；源码、分支、会话、封面和固定发行仍存储。拥有者从游戏库「已归档」筛选中恢复原工程，原成员权限随之恢复。工程名称只改变目录元数据，不重写分支名称或原生 Godot 文件。

`PATCH /creation-api/projects/:p` 接受 `expected_version`（工程 `permission_version`）及单独的 `name` 或布尔 `archived`。仅现有拥有者可执行，归档项目的恢复专门核验原拥有者，普通读写权限保持关闭。资料变化与后台操作共用版本 CAS；`bootstrap.projects` 继续只返回活动工程，`bootstrap.archived_projects` 只给拥有者返回恢复所需目录信息。工程拥有者归档最后一个工程后仍保有新建资格。
