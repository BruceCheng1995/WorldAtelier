# 打包资源验证提速

2026-09-09。第二阶段优化，接续 [整包复用和哈希缓存](BUILD-PERFORMANCE-RESEARCH.md)。唯一产品入口仍为 48910 原工作台。

## 实现

- 全部场景和预制件继续逐个在独立 Godot 进程运行，保留 180 次主循环上限、真实启动回执、错误扫描、当前权限和工具链检查。加入 `--fixed-fps 60`，以固定模拟步长执行，避免等待实时帧间隔。每次运行仍使用独立保存目录。
- 应用构建第一次导入成功后，在任何游戏运行检查之前，将精确固定源文件及本任务 `.godot` 导入结果复制到独立导出目录。保留文件时间戳，支持文件系统写时复制，绝不使用硬链接共享可写文件。
- 运行检查结束后，重新验证原源文件和导出快照。快照的新增文件、符号链接、丢失文件和字节变化均拒绝出包。运行检查后产生的文件不进入快照。
- 复用范围仅限同一次构建；不跨版本、工程、平台工具链或任务共享未知缓存。没有可用导入缓存时保留原双导入路径。有快照时省去第二次单独启动 `--import`，实际 `--export-release` 仍执行 Godot 自身的资源扫描和必要导入。
- `creator_build.timings` 保存装配、导入、快照、每资源检查、导出和压缩的真实耗时及成功/失败状态。`import_snapshot` 记录派生快照回执。缓存仍由原构建清理流程删除；固定工程、产物及记录保留。

这是构建流水线的技术检查优化，不增加会话自动验证，也不减少资源目录或改动源提交、公开发行及共享房间。没有引入额外并发、产品服务或全局缓存。

固定模拟步长的语义见 [Godot 4.6 命令行说明](https://docs.godotengine.org/en/4.6/tutorials/editor/command_line_tutorial.html)。它禁用实时同步；`Time.get_ticks_*`、线程、异步 IO 的墙钟时间覆盖与原等待方式不等价。构建通过仍不代表这些场景的完整玩法验收；需要真实时间的行为应由相应测试覆盖。

## 回归与正式启用
