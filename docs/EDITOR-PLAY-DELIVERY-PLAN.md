# 编辑、游玩与打包：可用版和完整版落地方案

日期：2026-09-09。状态：设计提案，尚未实施本方案。适用工程：WorldAtelier，唯一产品入口为 48910 原工作台。

> 2026-10-23 用户决定：快速编辑、快速 Play 保留为本波开发完成后的重点分析专题。本波优先处理运行隔离、Agent 试玩/交互/聚焦上下文、细粒度分支合并、原生离线往返和跨分支上下文；暂不启动本文的常驻引擎与快速运行性能改造。见[本轮决策与讨论](CREATION-NEXT-WAVE-2026-10-23.md)。本文目标数字仍是提案，不是已实现性能。

## 1. 决策与范围

建议先交付“可用版”，再在同一架构上补齐“完整版”。两个级别分别验收，前者必须能完整走通创建、修改、游玩、导出、明确发布；后者提升迭代速度、工程规模和编辑能力。它们不是两个产品，也不创建另一套游戏运行逻辑。

三项一级指标：

1. 编辑器内游玩速度：从点击 Play/重新开始，到正确版本的游戏已渲染且实际接受输入。编辑反馈作为前置子指标单独测量。
2. 打包速度：从请求到目标平台完整产物可下载，同时报告无改动复用、热增量和冷构建。下载耗时另列，不能用任务返回时间替代出包时间。
3. 功能完善度：按有明确分母的能力清单及真实工作流验收；不以按钮数量、启动成功或代码文件存在计算完成度。

两级均以 Godot 4.6、GDScript、Web Compatibility 渲染为基础支持域。完整版指该支持域内的完整创作闭环，不承诺复制 Godot/Unity/UE 的全部功能。原生文件中网页尚不会编辑的内容必须完整保留。

## 3. 目标与测量口径

以下数字是工程验收目标，不是当前性能承诺。先完成测量阶段，再锁定参考机器的 CPU、内存、系统、Godot 文件哈希和浏览器版本。主基准为本机或局域网、RTT ≤ 20ms、吞吐 ≥ 100Mbps、单用户前台窗口；不把公网网络速度归因于构建器。

S 样本：保留的 PvZ2D 固定源 `src-70a9b472e0bb5ee996fc71f70e3bc07589cb9114cddb0fee79d17a4d715e6348`，含 10 个资源。测量准备时记录全部源与导入产物大小，不以示例数字冒充真实规模。参数、脚本、贴图变更分别建立可重复固定版本。

| 指标，S 样本 | 可用版 P95 目标 | 完整版 P95 目标 |
| --- | ---: | ---: |
| 常规属性本地视觉反馈 | ≤ 100ms | ≤ 50ms |
| 常规属性从提交到中央确认并对齐实际编辑视口 | ≤ 1.5 秒 | ≤ 500ms |
| AI 场景/脚本提交完成后，编辑视口完成更新，无新媒体 | ≤ 3 秒 | ≤ 1 秒 |
| 同版本已有运行内容，点击 Play 到可操作，浏览器缓存热 | ≤ 3 秒 | ≤ 1.5 秒 |
| 修改普通属性/小段 GDScript 后立即 Play 到可操作，服务/浏览器缓存热 | ≤ 8 秒 | ≤ 3 秒 |
| 全新固定源、无派生缓存，浏览器引擎缓存热，首次 Play | ≤ 20 秒 | ≤ 12 秒 |
| 相同版本再次显式打包，已有完整产物可下载 | ≤ 1 秒 | ≤ 500ms |
| 参数/小脚本修改后的热 Web 完整 ZIP 可下载 | ≤ 12 秒 | ≤ 6 秒 |
| 无任何派生缓存的 Web 完整 ZIP 可下载 | ≤ 20 秒 | ≤ 12 秒 |

补充口径：

- “立即 Play”从用户完成最后一次编辑并点击开始计时，包含未完成保存、排队、准备与实际启动。后台预处理来不及完成时也计入，不能只统计命中缓存的成功样本。
- AI 指标从源提交成功计时，不包含模型推理；另报 AI 提交入口到源成功的耗时，防止把慢步骤藏在提交前。
- “可操作”由真实游戏首帧、正确版本、场景初始化和一次基准输入产生预期响应确认。只出现 `ready` 或 `STANDALONE_READY` 不够。
- “冷”分别标记服务端缓存冷、浏览器引擎缓存冷、浏览器内容缓存冷。完全冷浏览器另报端到端结果和实际下载字节，不能和热目标混算。
- 每类至少 30 次，冷样本使用独立空缓存，热样本在一次不计入统计的预热后执行；输出 P50、P95、最大值、失败/超时率、回退率。失败不能从统计中剔除。
- 热增量 30 次各自产生此前从未准备的新目标内容：属性样本使用同一现存数值属性的 30 个固定不同合法值，脚本样本使用同一函数中 30 个不同且可验证结果的常量；操作文件、数值、依赖扇出在 P0 固定。不能重复两个已准备版本，把内容缓存命中当作增量处理速度。新贴图/工具脚本/项目设置另测慢路径，不混入“小脚本”样本。
- P95 使用 nearest-rank（排序后第 `ceil(0.95 × N)` 项）。启动/保存 60 秒未完成、冷完整构建 180 秒未完成记超时；失败与超时按正无穷参与分位数，并单独报告。每组 30 次合法输入验收要求失败/超时为 0；即使 P95 达标，出现失败仍不通过。用于故障恢复验证的故意错误样本另组统计，不能稀释正常成功率。
- 另建 M 样本：10 场景、100 预制件、打开场景 1,000 节点、250MiB 原始媒体；作为规划夹具参数，并非当前实测工程。验收单属性修改不扫描/派生全部无关资源，分别报告实际依赖扇出与耗时。M 的数值 SLO 在首轮测量后锁定，未达标不称规模化性能验收完成。
- 4 个活跃分支同时编辑、同时有一个完整导出任务时单独测交互 P95，目标不超过对应单用户值的 2 倍。队列等待必须计入。
- 试玩运行时帧时间另作退化约束：相同固定场景和渲染设置，相比现有正确版本 P95 帧时间不恶化超过 10%。以上“速度”主要是迭代等待，不代表提高游戏自身 FPS。

## 4. 共同架构

中央原生源事务 → 不可变源版本 → 引擎处理变化和依赖 → 三个消费者：编辑场景、开发运行、正式导出。

| 层 | 职责 | 明确边界 |
| --- | --- | --- |
| 原生源与协作 | 真实 `.tscn/.tres/.gd`、稳定对象身份、版本冲突、撤销、权限 | 引擎生成的索引不是另一套场景源；客户端预测不推进中央版本 |
| 编辑工作进程 | 已打开场景、原生属性事务、导入与依赖缓存、编辑显示派生 | 是可丢弃的中央源工作副本；崩溃后从最后提交版本恢复 |
| 浏览器编辑视口 | 常驻 Godot 显示节点、选择、相机、布局、编辑反馈 | 普通编辑不运行作者玩法脚本；保留目前安全显示边界 |
| 开发运行内容 | 固定完整源、统一 GameRuntime/standalone、启动清单、调试桥 | 每浏览器独立一局；不从模型预览宿主启动玩法 |
| 正式产物 | 完整目标闭包、导出配置、产物校验、可下载应用 | 构建完成不发布；公开 Play 仍指向明确发布的固定构建 |

开发运行与正式导出共用 `project-snapshot.mjs`、同一作者文件与入口；允许准备/检查政策不同，不能出现不同的游戏装配逻辑。嵌入和新页面仍按同一不可变运行清单解析同一套实际游戏字节；公开玩家永远解析发布构建。

浏览器编辑与游戏执行环境分离：游戏不得因为与父页面同源而取得创作账号 Cookie、源码写权限或 Agent 工具权限。需要验证/收紧 iframe sandbox、消息白名单及资源访问票据；必要时使用无创作凭据的运行资源域，但不另起产品工作台。引擎二进制可公开缓存，私人项目内容不能靠不可猜哈希代替授权。

这是快速 Play 的启用门槛：P0 验证现状并选择隔离方式，P2 实施和独立验证后才开放新运行宿主。测试作者游戏通过 JavaScriptBridge、父窗口、Cookie/本地存储及 HTTP 访问不能取得创作权限，同时资源下载、调试消息、输入和独立存档正常。若采用不同 origin 或 opaque-origin sandbox，必须同时版本化当前同源桥的 origin 校验、消息会话能力和短期只读内容票据；不能只移除同源检查或接受所有 `message`。按威胁模型决定隔离方式，不在本设计阶段假定现有桥已通过。

## 5. 可用版：每次修改能迅速重玩，完整闭环可靠

### A1. 常规编辑走直接更新

优先支持 Transform、可见性、颜色、已有材质参数、基础 Control 属性和普通标量/枚举。浏览器立即对真实显示节点应用临时操作；中央仍通过 Godot 原生对象及保存逻辑提交，不用拼接 JSON 重建场景。

每个操作携带操作 ID、基准版本、项目/分支/文档、节点稳定 ID 与完整实例链。服务端返回确认版本和规范化值，客户端按操作序号对齐。冲突、拒绝和撤销只回退对应临时层，不能覆盖后续输入或其他人的已确认修改。滑杆拖动合并传输，松手立即提交；本地每帧反馈与不可变版本提交频率分离。

仅对有明确原生语义且不触发任意作者 setter/tool 代码的类型启用直接路径；有副作用的属性退回引擎处理并显示“正在更新”。恢复默认、预制件传播、共享资源/独有资源均由 Godot 判定；不靠客户端猜测继承。

### A2. 常驻编辑处理与缓存

增加由当前服务监管的按项目/分支和工具链隔离的 Godot 工作进程，预热只针对正在编辑的分支，不是每个用户、每个缩略图启动一个。初始池上限 2 个进程、空闲 5 分钟回收，后续以实测内存预算调整。

首次打开固定源后保留导入缓存及场景状态。常规属性通过命令协议执行原生更改/保存/重读；Agent 文件提交按变化路径重新载入受影响资源。引擎派生得到依赖与结果，浏览器只更新受影响文档。复杂操作暂可替换该文档场景，保持相机和选择，不能回到每次全项目派生。

进程不跨项目复用作者状态。遇到 `@tool`、自定义 Resource、静态脚本状态、扩展或无法证明安全复用的导入器，按能力分类进入隔离短任务。该回退计入真实耗时与功能表。常驻进程只读已提交内容并在受限工作副本操作；产物从被核验的版本登记，作者代码不得污染其他版本缓存。

事务具体顺序：核对基准版本与租约 → 在候选工作状态应用 → 保存候选原生文件并生成索引 → 校验变更文件/权限 → 中央 CAS 提交 → 将进程已确认版本推进到新 revision。保存失败、CAS 冲突或撤权后，不允许带着候选对象继续服务下一事务；能够证明逆操作完整时回滚，否则销毁进程并从最后确认版本恢复。进程返回的文件变化是候选输入，不是自行推进 head 的授权。异步派生与同分支写事务隔离版本；协议里包括进程 epoch，崩溃前的 ACK 一律拒绝。

### A3. 快速 Play 使用固定引擎与开发内容包

第一阶段不追求任意脚本的进程内热替换。每次 Play 启动干净的游戏实例，正确初始化作者 Autoload、InputMap、全局类、主场景和存储域。停止后恢复编辑相机；重新开始不继承本局内存状态。

将 Web 引擎模板与项目内容物理分开：按 Godot/模板/线程/扩展/渲染特性缓存 JS/WASM；项目仍使用 Godot 官方导出器准备完整 PCK。优先验证 `--export-pack` 路径，运行内容就绪不要求先复制全部引擎文件和生成 ZIP。HTML/启动配置仍按确切工程和导出选项生成，不能给所有项目硬套同一个 HTML。

`--export-pack` 仍隐含导入扫描，并不是“不做任何处理”。可用版消除的是重复引擎文件装配、ZIP 等待和开发路径的全资源运行检查；必须分别测量扫描、内容导出和浏览器初始化是否仍占主要耗时。

JS 引导器在游戏启动前预加载精确 PCK，并通过 `--main-pack` 启动。资源包中的项目启动配置必须在引擎初始化游戏时生效，不能先启动空游戏再挂包、手动模拟作者 Autoload。同版本重复 Play 复用引擎下载/编译缓存和已准备的内容，但使用新游戏实例避免旧单例、脚本、资源和存档残留。

运行内容状态为 `preparing → runnable`；仅在用户明确导出时创建关联的正式任务 `checking → packaging → downloadable`，失败/取消分别记录。Play 到 `runnable` 后不自动安排全资源正式检查。`runnable` 仅表示固定字节及开发检查就绪，不伪装正式 `completed` 导出构建。开发清单登记到同一构建/运行存储体系，最终 ZIP 仍引用同一组源和游戏内容字节；不得发布未完成正式检查的开发清单。备份登记包括运行清单、固定工程、模板身份及实际引用的内容产物，清理程序按引用保留，不让可复现运行只剩一个失效 URL。

兼容迁移采用版本化能力协商：旧 `play-build` 消费者继续只接收原固定 build 及其完成语义；新宿主声明支持运行清单后，才可接收新的准备句柄/清单类型。新类型不可伪造旧 `build_id`，也不可让旧客户端把 `runnable` 当作 `completed`。显式导出按同一 canonical identity 关联并补足目标平台检查；公开发行解析器始终只接受已完成且正式登记的构建。先完成接口、存储、访问票据和历史幂等回放的双版本测试，再切换 UI；停止旧支持须另行决定，不能静默改契约。

开发运行必要检查：源/配置合法、依赖导入和脚本解析、启动清单完整、当前用户可读。实际入口初始化在用户启动的游戏实例中确认，错误保留现场。普通 Play 不额外等待所有未使用预制件分别运行 180 次迭代。正式出包继续现有全资源检查；改变的是开发等待路径的覆盖范围，未触达预制件的问题可能在显式测试或出包时发现。平台不因此新增每次提交自动验收 Agent 或完成门禁。

源提交可以使旧准备结果过期，用户点击 Play 则将当前已提交版本固定；等待中的较旧普通预处理可取消，已明确请求的固定版本运行/导出不能静默改成最新 head。用户尚未提交的编辑先完成确认，不启动一个看起来像最新、实际落后的版本。

### A4. 正式打包保留全功能，复用准备成果

沿用内容相同的任务合并、完整文件校验、256 项哈希 LRU 和同任务导入快照。新增可核验的跨任务导入缓存：键包含引擎/导入器、平台及纹理特性、源字节、导入设置、依赖、UID/重映射相关输入。只缓存从干净导入阶段产生的可登记产物，不复制玩法检查后的可写工程。

构建输入变化后仅让受影响导入项失效；完整资源目录仍保留。动态 `load()`、字符串路径和目录发现不能用静态依赖扫描随意裁剪。开发内容包若与发布导出选项、字节码模式及工具链不一致必须重建；一致时可复用内容字节，补正式检查、装配和压缩。

先使内容可运行，再在显式导出时准备完整 ZIP。已有 ZIP 可直接返回；ZIP 不作为编辑与 Play 的先决条件。完整独立下载包仍含需要的引擎和资源，不能以依赖本机缓存的链接集冒充可下载应用。

### A5. 用户可见行为

属性数值立即显示，状态清楚区分“保存中 / 已保存 / 场景更新中 / 已更新”。旧显示有版本标记；失败不显示完成。普通快操作不弹整页加载层，不清空场景，也不抢焦点。

Play 区显示具体阶段“保存修改 / 导入资源 / 准备运行 / 启动游戏”。已有游戏继续运行在原固定源，源码变化仅提示有新版本。默认点击重新开始才采用新源；绝不因为 AI 保存而自动重开当前一局。公共发布仍是明确动作。

## 6. 完整版：增量处理、受控运行更新与完善的编辑能力

### B1. 真正按依赖增量执行

在可用版缓存与进程协议上增加可持久化的依赖图：源文件 → 导入结果 → 场景/预制件 → 编辑派生 → 开发内容/平台导出。正确处理删除、改名、循环依赖、共享资源、嵌套实例、UID 和导入设置。更新后以原生重新载入的结果对照，不允许增量缓存成为新权威。

主视口只接收当前文档变化及必要依赖。缩略图按可见区域和对象版本延迟刷新，绝不阻塞提交/Play。优先级为交互编辑、明确 Play、明确导出、缩略图；配合每项目配额与老化调度，导出不能无限饥饿。节点密集或扇出很大的预制件更改按批次执行并报告真实进度。

### B2. 编辑媒体与运行内容分块传输

编辑视口可独立获取内容寻址的已导入媒体，不再因一张新贴图重出整个编辑包。只传浏览器缺少的块，保持目标平台纹理格式和导入回执。

运行端逐步将 PCK 单体传输改为精确内容清单/增量下载与本地完整挂载。分离“服务端重新处理”“网络只下载差异”“引擎已加载对象更新”三个问题。首次启动前必须已具备完整启动依赖；未访问的场景可延后传输仅在原生加载路径被完整支持、动态依赖可解析时启用。

第一条落地路径明确为：服务端登记完整目标 PCK 及块清单 → 浏览器按不可变块哈希只下载缺失块 → 重建并校验整个目标 PCK → 新 Engine 用这个完整主包启动。块清单包含顺序、偏移、长度及整个 PCK 哈希；缓存缺失或增量收益不足时退回完整下载。这只优化传输，不声称已经减少服务端导出耗时。测量块复用率，并覆盖 PCK 输出变化导致块复用率低的情况；同时测块缓存、重建缓冲区和 MEMFS 的峰值内存，采用可释放的分段处理和明确大小上限。只有此路径稳定后，再单独评估场景延后传输与运行中补丁挂载。

不能假定 `load_resource_pack` 会替换已加载 Resource、重新执行 Autoload 或应用项目设置，也不能依赖它自动卸载旧包/隐藏删除文件。第一阶段仍启动新游戏实例；进程内增量挂载只有在路径覆盖、删除、preload 缓存、UID、内存回收和回滚均验证后才开放。否则退回重新启动同一固定内容的新实例。

浏览器使用缓存复用 JS/WASM 下载与编译结果，不承诺保留一个被暂停的完整游戏快照作为“干净启动”。只有冷内容下载可以复用，游戏初始化必须仍符合统一入口语义。

### B3. 游玩中调参，按行为明确承诺

引入作者可声明的参数应用策略，默认 `restart_required`：

| 策略 | 行为 | 示例 |
| --- | --- | --- |
| `live_value` | 支持的原生字段在帧边界事务应用；实际回执后才标记生效 | 已定义动态读取规则的移动速度、灯光强度 |
| `recreate_component` | 仅对具有明确销毁/重建契约的组件执行局部重建 | 可重建的特效发射器 |
| `restart_required` | 继续旧版本，提示重新开始应用 | 普通脚本变更、Autoload、InputMap、未知 setter |

默认试玩源固定不自动变化。用户选择“应用到本局”时记录本局基准源及应用操作清单；运行观察/Agent 附件绑定该清单，不能把混合状态冒充某一源版本。若更改应长期保存，仍通过中央源事务处理；临时调试参数不悄悄写回源。

脚本结构、原生扩展及项目启动配置不承诺通用状态保留。确需保留运行状态，项目实现版本化的导出/恢复接口，候选实例验证后切换；失败留在旧实例。该转移是新实例接管，不称进程内热重载。当前原生共享世界属于独立能力，普通 Play 方案不扩展或变更其权威规则。

### B4. 编辑能力从参数面板补齐为创作工作流

完善资源选择与依赖提示、嵌套预制件独立编辑、实例差异及批量还原、2D/3D 与 Control 布局、材质/动画/音频/粒子编辑预览、真实脚本错误定位、运行对象检查，以及两用户同场景冲突恢复。未知原生属性始终往返保留。

工具脚本和导入插件只有隔离执行并具备可解释编辑结果时才纳入支持。完整版不通过在主创作页面直接执行任意作者脚本来换取预览能力。资源能力按网页可编辑、仅可保留、可运行、需原生工具四种状态列明。

### B5. 发布与平台能力

持续复用相同平台内容/引擎文件；导出独立 ZIP 时仍补齐完整实体文件和完整性回执。远端 worker/对象存储是后续容量选项，不是当前本机提速的前置条件，未授权前不创建外部部署或账号。

Web 为必验平台。桌面导出先选当前可验证的 macOS 非签名测试包，再按所需环境补 Windows/Linux。Android/iOS 分别需要工具链、设备和签名；缺少环境标记未验收，不把配置项存在算成功。Godot 4.6 的 Web C# 不支持；GDExtension 仅接受实际具备 Web 构建且模板支持的扩展。完整版也不抹掉这些平台边界。

## 10. 独立验收与发布回退

至少保留三个真实工作流：PvZ2D 改攻击力/刷新实例/进入战斗；3D 场景改模型材质/嵌套预制件/相机与碰撞；UI 场景改 Control 布局/切关卡/暂停重开。每个同时验证源文件、实际显示/玩法与重开后的结果。

故障矩阵覆盖：权限撤销、两个用户同字段冲突、提交后切分支、连续 AI 文件提交、撤销过程中返回旧 ACK、工作进程崩溃、缓存缺失/篡改、删除或改名资源、脚本解析错误、导入错误、网络断开、准备中停止，以及运行中的源更新。

数据对照覆盖：预制件默认跟随、实例覆盖、共享 Resource/Make Unique、未知文件原字节、脚本全局类和 UID、Autoload 执行顺序、InputMap、持久存档域和嵌入内存域。连续至少 100 次 Play/停止检查单例状态、音频、文件系统及 WebGL/进程泄漏；持续编辑 2 小时检查池回收和版本缓存边界。

性能必须在实际浏览器输入和真实 Godot ACK 下测量；协议双桩只覆盖时序，不替代性能与玩法证据。独立测试在候选实现上执行，不重建用户已删除的合成描边测试场景，不给每个创作会话自动安排验证 Agent。

渐进启用三个可回退开关：直接属性更新、常驻编辑工作进程、开发内容快速启动。按项目/分支启用，不能混用不同协议的回执。旧固定源、历史构建、发布指针、会话与附件不迁移重写。关闭开关退回当前兼容路径；新的源提交仍是合法原生文件。正式启用使用原服务守护启动流程，只在确有后端变更需要时受控重启。

- [Godot 4.6 ProjectSettings](https://docs.godotengine.org/en/4.6/classes/class_projectsettings.html#class-projectsettings-method-load-resource-pack)：资源包挂载接口及目录枚举等边界。
