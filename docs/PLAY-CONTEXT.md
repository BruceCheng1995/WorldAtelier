# 从试玩继续创作

2026-10-23。本轮在原工作台加入试玩上下文与跨分支会话延续。下面描述实现契约；真实主入口、Godot Web 与 Agent 联调证据由独立验收另行记录，不从本文件或组件测试推断。

## 用户流程

当前浏览器在试玩时保留最近 60 秒的本地过程。聊天输入区显示可移除的“附带试玩过程”，可查看关键画面与步骤、缩短范围，或主动延长到 3 分钟、10 分钟。没有发送时不持续上传过程。停止、换游戏、换分支、重开运行或退出账号会清空当前本地缓冲。普通切换到另一个会话时取消自动附带；用户明确勾选或在新会话“指出这里”后，可以引用同一当前试玩。

“指出这里”沿用个人观察：独立局暂停这一局，明确加入的共享世界只冻结个人呈现。用户在固定画面上点一下或框出范围，不必打开对象树，空白、光效、UI 间隙和已消失内容的历史画面都可成为讨论范围。聚焦不会写源稿，也不会把运行位置当作场景初始布局。

发送时固定当时的过程、焦点、观察与关键画面。Agent 首屏取得简短步骤和少量实际图片，需要时按页读取事件、对象和其他关键画面；当前窗口仍有效时，可以请求一次新的只读观察。新观察不会更新旧消息，不注入操作，不自动暂停或重启游戏。Agent 的修改仍通过既有中央原生源事务提交；用户重新试玩后才进入修改后的版本。

取消附带会移除同一默认片段关联的图片。上传回执不确定时先核对原幂等请求再移除，不能让画面上已取消的记录隐藏在服务器草稿中。改变已准备片段的时长或焦点会替换旧的默认片段，保留其他用户添加的附件。

## 记录的边界

- 只记录游戏画布内的操作和运行观察，不记录聊天输入、账号输入、其他网页或桌面活动。原生 LineEdit/TextEdit 的输入事件只保留字段类型和发生动作，正文、Unicode、剪贴板及组合输入不入事件；自动关键帧遮盖已识别的文本输入矩形。自绘文本输入无法仅按 Godot 节点类型识别，属于当前边界。
- 本地环形缓冲同时限制时间、事件数和字节数。单包过大、事件缺口、对象扫描截断、关键画面失败或传输裁剪都会记录缺口。缺失不是零值，也不表示未发生操作。
- 关键画面不是逐帧录像。输入轨迹说明用户做过什么，实际效果需要画面、引擎状态或权威回执支持。没有确定性回放承诺。
- 通用原生观察读取实际节点的内置空间/UI 属性及显式 `wa_observation` 纯数据元信息；不调用作者方法，不通过任意脚本 getter 探查状态，不展开 Resource、Object 或 packed 二进制数组。作者上报仍标为作者数据。
- 源实例使用完整固定地址和版本校验。动态 PackedScene 节点可以保留来源预制件；只在运行期存在的节点保留本局身份。名称不是映射依据，所有观察均不自动授予写入目标。
- 每张关键帧保留当时可用的投影与时间差。只有冻结个人呈现，或截图与观察实际 tick 相同且测量差不超过 500 ms，才提供对象候选。否则仅保留屏幕意图。历史画面不会套用当前对象的屏幕范围；投影包围框候选也不等同逐像素遮挡命中。
- 运行身份绑定固定构建、iframe nonce、实际场景与场景代次；共享世界还绑定 world/epoch。nonce 只是桥接身份，不是创作凭据。服务验证权限和源引用，不能因此宣称客户端画面或作者 telemetry 已被权威认证。

当前预算：默认 60 秒，最多 600 秒；本地 8 MiB、1,200 条事件、每秒最多 256 个通用节点观察；一次保存最多 4 张关键帧、3 MiB 请求内容，默认最多 3 张进入视觉输入，其余仍可按需读取。节点遍历和文本遮盖检查有独立扫描上限；遮盖检查不完整的自动画面不会进入记录。

## 跨分支继续

会话设置中的“到另一个分支继续”固定来源会话、消息截止点、来源 head、目标分支 head 和继续目标，创建新的私有会话。可以取消携带试玩观察；显式空选择不会变成“带入全部”。旧草稿、旧执行线程、进行中的命令、目标租约、审批和游戏输入控制仍留在原会话。

历史消息和附件保留原来的分支与版本。目标分支的相同、已改变、已删除或无法确定映射单独记录，不改写来源身份。以后新增来源消息或修改目标源稿，不改变这份历史。读取历史同时检查来源和目标会话权限；后来分享目标会话不会自动公开原私有会话。

## 接口与验证

实现与接入点见 [集成说明](handoffs/play-context-INTEGRATION.md)。只读 Agent 工具为 `play_context_read`、`play_context_current` 和 `session_context_read`；完整观察位于不可变记录和按哈希图片文件中，默认模型上下文仅投影简短摘要与引用。

作者检查分别使用真实临时 SQLite/HTTP、实际 headless Chrome DOM/Canvas，以及由 `project-snapshot.mjs` 装配的真实 Godot canonical 工程。Godot 测试使用 headless、Dummy 音频和进程内输入，检查动态来源、源字节不变、文本事件脱敏、陈旧代次拒绝和无作者 getter 执行。浏览器组件测试中的游戏消息和底图明确为夹具，不计作完整 Godot Web 或真实 Agent 任务验收。
