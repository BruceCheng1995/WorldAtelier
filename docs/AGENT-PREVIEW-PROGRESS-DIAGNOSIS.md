## 共性字体错误

两款作者代码均曾直接依赖 `res://atelier_runtime/fonts/CreatorUI.tres`。坦克约 21:11:19、小小梦魇约 21:21:29 的提交失败涉及该路径无法打开/预加载。

该字体属于平台注入的运行文件，在 Agent 的完整运行工程中可见；`submit_native_workspace` 按设计排除未修改的框架文件。作者场景或脚本仍直接引用此路径时，中央原生源导入缺少该依赖。于是本地运行成功、中央提交失败。两款 Agent 均选择自行去除该直接依赖。

`tools/release-template/standalone.gd` 已安装默认主题字体。应明确作者源码与框架资源的边界，使用默认字体或合法的作者源资源；不能靠把框架文件写入游戏源稿掩盖问题。

## 进度可见性缺口

1. `services/creation/native-agent-workspace.mjs` 的 `nativeWorldApiGuide` 说明如何提交完整工作区，未明确先保存可见场景骨架、随后按可用里程碑提交。此次两个 Agent 均长期只在工作目录制作和测试。
2. `apps/creation-workspace/workspace.js` 的 `renderConversation` 将同一次请求的较早 assistant 消息折叠进默认关闭的“过程更新”，仅直接展开最后一条。持久消息未丢失；“看不到”与“没有产生”应分开诊断。
3. `services/creation/agent-runs.mjs` 的 `projectDevelopment` 只为已有 `targets` 投影对象开发状态。空游戏无附件目标，首次提交前 `targets=[]`，因此没有对象施工标记。顶部真实运行人数仍可显示，但不能说明场景为何为空。
4. `syncMainPreview` 的“场景已更新”只表示该中央源版已加载。没有同时明确“Agent 正在本地制作，尚未提交本轮修改”，容易使空场景看起来像加载故障。

## 建议修复边界

- 明确阶段保存：先提交可导入的真实场景骨架，每个可用里程碑通过现有中央事务保存；不等待最终测试，不引入自动验收门禁。
- 基于真实运行和成功提交回执显示“尚未保存本轮修改 / 已保存并更新场景 / 保存失败”，并保留会话入口。没有目标对象也应有分支级开发状态。
- 让当前运行的最近进度容易看到，并保持用户主动折叠历史的选择；不以虚构百分比代替实际进度。
- 明确禁止作者源文件直接依赖仅运行工程可用的框架资源，尤其是注入字体；应提供可执行的正确用法及针对性的依赖错误说明。
- 中央原生源稿继续作为唯一内容权威。不得自动预览正在半写入的私有工作目录，不绕过源事务、版本冲突和运行租约。
