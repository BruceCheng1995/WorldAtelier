## 1. 产品定义与已确认决定

世界工坊是一个多人共同创作游戏的工作台。协作者在同一分支的共享场景里，可以对话创作、直接操作对象、编辑可复用预制件，并随时在当前网页视口运行同一创作版本的 Godot 游戏。

中央服务管理这些创作事实和在线世界；下载、构建、发行、检查点是支撑能力。固定战役是一个示例工程，不能成为所有新游戏的起点或通用编辑器的数据结构。

用户已确认：

- **Play 默认在当前网页视口运行 Godot Web 游戏。** 桌面 Godot 是可选的额外目标，共用资源与行为契约；默认流程不弹出本地窗口。
- **暂停只冻结自己的检查视图。** 其他玩家与服务器继续运行；个人相机可以漫游，网络与编辑操作继续工作。按钮文案采用“暂停检查 / 返回实时”，并显示“仅我的视图”。
- 主干与分支都是可进入、可协作、可试玩、可持续开发的游戏版本；主干只是默认集成目标。
- 检查器只有“对象”“协作”两个 tab。逻辑组件属于对象/预制件内容，不再提供全局“规则”tab。
- 每个分支、每个协作者都拥有**多个长期 session**；任务是 session 中可执行的 Agent 目标。

## 2. 从空游戏开始的主流程

1. **创建游戏。** 填写名称后进入分支面板，生成 main。默认只有空资源目录和编辑环境；可以明确选模板，但不能偷偷复制星屿远征。
2. **进入共同创作。** 打开 main 工作台，在自己的新会话中输入“创建一个有出生点和平台的场景”。会话展示真实 Agent 进度、创建的场景资源及可点击结果。完成后场景自动在编辑 tab 打开。
3. **通过对话创建预制件。** 例如“生成一座可以交互开门的小屋”。Agent 可调用 Blender 制作模型，编写交互组件，在独立工作区验证，生成可复用预制件定义。模型资产、逻辑组件和预制件有分别可追溯的版本。未摆放的小屋也出现在“全部预制件”。
4. **编辑布局。** 拖入小屋形成实例；使用 XYZ 操作柄移动、旋转、缩放，或者对 Agent 说“把小屋放到这个坐标”。另一位协作者在同一场景及时看到持久化后的编辑，拖动过程可看到临时预览。手动与 Agent 使用同一事务协议。
5. **独立 Play。** 在当前网页视口，从点击时固定的源版本运行场景。每个窗口拥有独立模拟和游戏进度；角色与输入由游戏内容显式定义，空场景不自动生成玩家。协作者继续共享源稿编辑，不共享这一局试玩。启动失败明确显示错误，不回退到旧发行。只读玩家仍使用服务允许的可玩源版本。
6. **暂停观察。** 只暂停当前窗口这一局，游戏 UI 默认隐藏。自由相机可环绕、平移、缩放和漫游；「显示游戏 UI」仅恢复可见性，不恢复游戏按钮交互。所见对象可只读检查；固定到会话时明确固定该版本的源对象，不冒称中央在线世界观察回执。
7. **继续或重新开始。** 继续运行恢复这一局的状态、游戏 UI 和游戏相机；重新开始销毁这一局，从当前源版本初始状态启动。停止并编辑恢复原编辑视口与相机。新页面游玩复用现有 Web 出包功能。

编辑/试玩/个人检查切换时保留当前分支、打开的场景和预制件 tab、选中对象、相机书签、会话与尚未发送的附件。运行时对象已删除时保留历史引用并提示原因，不偷偷选中另一个对象。

用户于 2026-09-07 确认：默认只显示场景树、视口与属性，聊天会话移至侧边抽屉。抽屉覆盖右侧区域，关闭后不保留聊天占位；工作台使用窗口剩余空间，树和属性各自滚动，主视口不再随整页滚出屏幕。开关抽屉保留当前会话、草稿和两处 Godot 视口实例；关闭、Esc 或点击场景返回编辑。

从对象属性添加附件、Agent 目标入口或共享会话入口进入时，自动打开对应会话。抽屉内再打开弹窗时，Esc 优先关闭弹窗。当前会话仍是本页示例，不因抽屉改造成为真实 Agent 后端或持久会话。

视口内的操作柄、相机、吸附和变换历史约定见 [3D 交互](3D-INTERACTION.md)。小于 640 px 的窗口默认优先视口，通过顶部“树”“属性”打开对应面板；大窗口默认保留三栏，并支持手动收起或最大化视口。

实际模型预览的实现范围、启动方式和验证见 [真实模型预览接入](MODEL-PREVIEW.md)。

[可点击工作台设计稿](design/creation-workspace.html)用于检查入口、选中联动与附件流转。它是使用演示数据的布局说明，不是 Godot 视口、多人服务或 Agent 执行证据。

### 多分支入口

每张卡展示分支名称、来源、最近修改、在线协作者和“进入创作”。主干使用同样大小和功能的卡片，只增加默认目标标记。面板也有“从此版本分出”“比较并合并”。不要求分支先合并才能 Play，也不把分支当临时试验弹窗。

“从当前状态分出”将移动的 head 解析成不可变版本后分叉；若用户正检查旧版本，清楚展示“当前所见版本 / 最新编辑版本”选择。需要继承试玩进度时额外固定检查点，并核对它和资源版本的兼容性；普通内容分支不默认携带背包、战斗和在线玩家状态。

### 场景、预制件、实例、资产

| 对象 | 用户看到的能力 | 保存的事实 |
| --- | --- | --- |
| 场景 | 新建、打开、层级树、多人编辑、选择入口场景、试玩 | 稳定节点、层级、完整 3D 变换和预制件实例 |
| 预制件 | 全部目录、筛选美术/带逻辑、独立编辑、保存版本、实例化 | 可复用场景定义及固定资产/逻辑依赖 |
| 场景实例 | 拖放、修改实例参数、恢复覆盖、升级定义 | 指向预制件版本的引用，加本实例覆盖 |
| 模型资产 | 实际可旋转预览、导入 GLB、Agent 调用 Blender 生成 | 不可变模型文件哈希、来源和依赖 |
| 编辑锚点 | 创建空白对象、操作柄定位、添加坐标附件 | 稳定 ID 和变换，不要求有模型或物理实体 |

双击预制件在独立 tab 中打开其定义。编辑地面、灯光和预览相机属于编辑环境，不写入预制件。对象检查器明确显示正在改“实例覆盖”还是“预制件定义”。保存定义产生新版本，依赖更新可查看受影响实例；冲突实例等待处理，不静默抹掉实例覆盖。

模型导入与生成都进入候选资源流程。生成按钮把请求和选中对象加入当前 session；执行端没有可用 Blender/生成器时给出实际不可用原因，不用占位模型或固定回复冒充已生成。对象组件展示逻辑引用、参数及“在会话中修改逻辑”，不重新引入规则 tab。

### 协作与状态表现

同分支同场景的对象、资源目录与已提交变更共享；个人选中对象、相机和未发送草稿分别保存。协作 tab 展示成员、当前编辑者、对象批注、关联目标与变更历史。

选中对象保持青色包围与描边；实际被编辑/正在执行关联目标时展示橙黄维护圈、黄黑施工标识与可读状态。一个对象可以关联多个目标，不能任一目标完成就把整个对象标成已交付。维护状态源于具体运行和变更事件，不使用倒计时或任意对象 hash 变化自动结案。

## 4. 个人暂停的准确含义

这里有三份不同的数据：

| 数据 | 谁负责 | 本人暂停时 |
| --- | --- | --- |
| 共享创作文档 | 中央文档事务服务 | 继续同步协作者和 Agent 的修改 |
| 在线游戏状态 | Godot 权威世界 | 继续模拟和同步，其他玩家正常玩 |
| 我的检查快照 | 当前客户端，必要时服务端保留 | 固定发行、tick、对象变换；相机继续工作 |

暂停时停止本人移动/攻击等玩法输入并发送零输入；角色仍处于在线世界，可能受玩法影响。“个人暂停”不自动产生无敌、回滚或全房间暂停。页面失焦也不能让最后一次移动持续生效。

为了保持空间观察一致，检查视图固定当时的资源版本和模拟变换；后台接收最新状态。协作者的后续变更以“检查后发生的修改”提示呈现，可显式刷新检查基线。用户编辑对象时作用于共享创作文档，视口以编辑轮廓/草稿叠层表现；动态物体当前所在位置不会自动变成它的场景初始位置。

从旧检查快照编辑对象时，先核对稳定 ID 和目标字段版本。其他人已改同字段或删除对象，展示差异并让用户处理；不能用旧快照覆盖最新场景。返回实时取得当前基线并清除旧输入和陈旧插值缓存。断线、版本切换或恢复失败时留在可解释的检查状态，重试，不伪报已接续。

## 5. Session、目标、对象批注与坐标

```text
游戏 → 分支 → 协作者 → 多个 Session → 消息 / 上下文附件 / 多个目标
目标 → AgentRun → 工具调用 → ChangeSet → 验证记录 → 资源版本 → 现场应用回执
```

Session 是持久化创作会话，和登录 token、游戏控制权、临时 checkout 无关。切换分支后打开该分支下的会话集合；后台旧任务继续绑定原分支，不跟随界面偷偷切换。重新登录或服务重启后，历史、附件、产出和待处理目标仍可恢复。

分出内容分支不会复制所有人的私人对话。用户可以显式“带上下文继续到此分支”，创建新 session 并保存来源；历史附件仍指向原来的对象和版本。新 Agent 会话默认向项目成员公开，私有需手动设置，已有会话保持原可见性；协作权限和会话可见范围要分开核对。公共维护标识只展示对象、执行者和操作状态，不披露私人目标正文、附件或工具参数。

批注的流程：

1. 在视口或层级树选中对象，点击“加入当前会话”。
2. 输入框出现可查看的对象附件：游戏、分支、场景、稳定对象 ID、预制件版本、所见版本、当时的参数和位置；可以添加一句批注或多个附件。
3. 点击发送后才加入消息并触发目标；仅选中、仅附加不自动执行 Agent。
4. Agent 可以按附件读取原始观察和当前版本差异，工具写入必须明确目标分支和基线。

精确位置的流程：创建“空白锚点”→用操作柄放到预期位置→“添加坐标附件”→在会话中输入“把入口放这里”。附件同时保存父级局部变换和世界坐标、单位、坐标空间、场景原点/版本、祖先变换身份及观察相机。嵌套预制件对象还保存完整实例路径，避免两个相同预制件里的内部节点互相混淆。发送后是不可变快照；之后拖动锚点或改名不会改写旧消息。可以主动添加一个更新后的附件。纯编辑锚点默认不导出为玩法碰撞对象。

任务不能再等同于“对象上有一张待办卡”。它有明确目标、输入基线、一个或多个执行轮次、工具事件、候选变更及目标验证。运行时报告“已应用”和目标报告“已达到验收条件”分别记录；改对象名称不能自动完成“实现交互开门”。

## 6. 分支合并和持续开发

从固定源版本分支，两个分支共享不可变资产存储，但文档 head、编辑通道、会话集合和在线世界相互隔离。手动合并采用共同祖先与稳定 ID 的三方比较，提供对象、预制件和依赖变化预览。

不冲突的修改可合并；同节点变换、删除与修改、预制件内部节点变化、行为类型变化都必须有明确冲突结果。合并只提交目标分支的新资源版本，不立即覆盖其运行世界，也不混合双方的玩家进度。合并后源分支仍存在，可以继续开发并再次合并；不能每次重复应用已经合入的更改。

## 7. 交付判断

新的总验收旅程是：**两个真实用户和一个真实 Agent，从空游戏完成新场景与美术/逻辑预制件，共享摆放，当前 Web 视口 Play，个人暂停观察和精确批注，再分支独立开发、手动合并并继续协作。**

旧战役通关、自动生成的测试 .tscn 数量、设计稿能点击或后端端点存在，都不能替代这条旅程。具体步骤、失败条件与证据要求见 [新的创作验收](CREATION-ACCEPTANCE.md)。

## 拖入预制件创建实例（2026-09-09）

编辑模式下，可从预制件目录拖动卡片到当前场景视口。交互参考 [Figma 从资源面板创建组件实例](https://help.figma.com/hc/en-us/articles/360039150173-Create-and-insert-component-instances)：拖动时在画布中显示实际尺寸的半透明预制件预览，名称提示跟随光标，不使用整片视口的投放框；普通点击卡片仍打开独立预制件编辑器。松手后按当前相机查询可见模型的实际三角面交点，三维无命中时回退 Y=0 地平面；二维按当前画布缩放和平移还原坐标。无法取得有效落点则不创建。

创建复用现有中央原子事务：原生文档保存真实 PackedScene 引用和实例位置，保留定义根的旋转、缩放及其他属性，未覆盖属性继续跟随定义。新实例自动编号、选中，可通过一次撤销移除。属性与位置写入前后均校验固定源版本、文档、视口代次与编辑权限；取消拖拽、拖到视口外、只读或运行模式不创建。预览加载中须等待当前场景就绪。

拖动预览只加载当前固定原生构建中已烘焙、无作者脚本的预制件，不加入源对象、碰撞或协作选择。拖出视口隐藏，拖回继续；Esc、松手、文档切换或超时回收。只有松手后的现有原子事务会生成真实实例。

## 2D UI 选择提示（2026-09-09）

2D UI 中，同一协作者的多选合并为包住全部所选控件的最外层选中框，名字在该框旁只显示一次。父子控件同时选中时，不再叠加内部选择框。多人选择相同范围时，各自颜色向外排列；Agent 使用独立开关控制的动态虚线。同一批 Agent 操作跨多个控件时共用一个提示。

控件编辑复用上述选中框，不额外绘制蓝色边框。单选仍保留控件缩放手柄；多选隐藏主对象的内部手柄，避免让它看起来像另一个选中框。选择状态、控件层级和源文件不因提示合并而改变。

名称合并由 2D、3D 共用：同一用户或同一批 Agent 操作无论选中多少对象，只显示一个纯名称，锚定全部可见选择的外侧范围。混合选择 UI 与三维对象也不重复显示名字；同名的不同用户仍按身份分别显示。关闭 Agent 描边同时隐藏对应名字，取消选择不残留提示。3D 对象继续使用原有模型轮廓描边。
