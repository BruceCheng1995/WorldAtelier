# 本轮创作能力决策与落地讨论

日期：2026-10-23。状态：本轮功能已接入原工作台。下文保留用户决策与设计基线，实际运行、独立验证、失败修复和边界见[本轮独立验证](CREATION-NEXT-WAVE-VALIDATION-2026-10-23.md)。

实现入口：[作者游戏运行隔离](RUNTIME-ORIGIN-ISOLATION.md)、[试玩上下文](PLAY-CONTEXT.md)、[原生合并与离线往返](NATIVE-MERGE-OFFLINE-INTEGRATION.md)、[本机客户端接续](NATIVE-CLIENT-CONTINUITY.md)。统一产品入口仍是 `http://127.0.0.1:48910/creation-workspace.html`。

## 1. 已确定的范围

| 议题 | 用户决定 | 本轮处理 |
| --- | --- | --- |
| 作者游戏与创作账号隔离 | 开发 | 覆盖所有作者代码运行入口及上下文通道 |
| 快速编辑、快速 Play | 本波结束后重点分析 | 保留为后续专题，沿用 EDITOR-PLAY-DELIVERY-PLAN，不混入本轮引擎性能改造 |
| 多分支细粒度合并 | 由工程方设计落地；细粒度、高效率、低损失 | 建立在线分支与离线回传共用的原生源合并内核 |
| 原生离线往返、客户端接续 | 由工程方主导；效率优先 | 增量同步优先，源内容与游玩状态分别处理 |
| 分支之间延续创作上下文 | 开发 | 固定来源，新建目标分支会话，保留历史 |
| 对象相关 AI 创作 | 重点是 Agent 获取当前上下文 | 试玩状态、交互过程、点选/框选焦点优先，不扩张为大量引擎操作按钮 |
| 长期托管与资源管理 | 之后讨论 | 本轮不扩展远端调度、租户与容量平台 |
| 完整多平台交付 | 搁置 | 不以本轮客户端接续为由扩展所有平台出包 |

用户已选择：**当前浏览器默认保留最近 60 秒试玩过程；发送消息时附带步骤摘要和关键画面；长流程可主动延长。** 这不是整局持续上传或全桌面记录。

## 2. 主体验：在游戏里表达意图

目标流程：试玩 → 点中或框住关注内容 → 描述问题或希望的变化 → Agent 理解当时画面、前置操作与源稿来源 → 修改中央原生工程 → 用户运行修改后的版本。

例如：用户走近门、点击交互但门未打开，框住门并说“刚才点了两次，应该能打开”。Agent 获得点击前后关键画面、相关操作与错误、门的运行身份及可确定的源引用，按需读代码，保存修复。原来这一局保持其固定版本，用户明确重新试玩后检查结果。

保留现有直接编辑能力，但用户不必理解节点树、组件或资源路径才能发起修改。用户意图与 Agent 的实现位置分别记录；焦点是调查范围，不自动成为全部可写目标。定义、实例、生成器和共享资源的影响范围由 Agent 查清。只有会改变用户含义的歧义才需要询问。

正常试玩输入不同时承担选取/编辑动作。用户用统一的“指出这里”入口或快捷键进入个人观察后点选、框选；先清理玩法按键，避免切换后角色仍移动。瞬时特效或已经消失的对象可直接指向最近关键画面。独立局沿用本局暂停，明确加入共享世界时只冻结个人呈现；无需寻找场景树才能反馈问题。

现有基础可以复用：对象/空间不可变附件、点选/框选/笔刷、截图划线、相机、固定构建身份、预制件测试事件及图片输入。当前编辑态批注与普通 Play 的运行观察仍有断点；不能把已有 telemetry 当成任意原生游戏的完整业务状态。

## 3. 统一观察上下文

### 信息层次

| 层 | 保存内容 | Agent 默认读取 |
| --- | --- | --- |
| 用户意图与焦点 | 原话、对象/多选、屏幕框、空间点/区域 | 原话、焦点摘要及映射状态 |
| 固定身份 | 项目、分支、源版本、构建、运行实例、实际场景及场景代次 | 精简身份，避免改错分支或关卡 |
| 当前观察 | 关键画面、相机、可观测属性、错误、源姿态与所见姿态 | 代表画面与相关属性；其余按需 |
| 最近过程 | 时间范围、操作、场景切换、状态差异、关键帧、事件缺口 | 几条重要步骤，原始片段分页读取 |
| 源关联 | 完整实例链、定义节点、来源预制件、生成者线索 | 能校验的定位；未知项明确保留 |

观察记录继续引用中央原生源；不新建第二份可写 JSON 场景。图片、事件段和大材料以不可变引用保存，不把逐帧画面、整棵 SceneTree、Resource 或二进制展开进提示词。

### 60 秒回溯

- 只记录当前游戏视口内的操作、运行变化和必要关键帧；不记录工作台聊天、账号输入或其他应用活动。文本输入默认记动作与字段，不收集输入正文。
- 采用浏览器本地有界循环缓冲；连续移动合并、关键事件触发取帧。时间窗之外还要有事件数和字节上限，超限明确标记缺口，不能无界积累。
- 用户发送消息时默认固定当前绑定运行最近 60 秒的可用片段及焦点，可见地列出附带范围；不要求逐次确认，允许移除片段或缩短范围。消息所属项目/分支/会话与运行不匹配时不自动附带旧窗口缓冲，用户可显式引用历史观察。长流程由用户显式延长。
- 未发送缓冲不持续上传；已发送内容按原会话权限保存为不可变附件。退出账号、项目切换等不得串入别人的缓冲。
- 第一期提供操作时间线和关键帧，不承诺逐帧录像或确定性重放。输入只能说明做过什么，效果需对应画面、引擎观测或权威回执。随机数、物理、网络和异步行为可能阻止精确复现。

### 当前与历史分开

消息发送时固定“当时发生了什么”。Agent 按需请求“现在的状态”时生成新观察，不能更新历史附件。只读观察句柄绑定当前窗口、运行身份和场景代次，停止、重开、切分支或撤权后失效。

普通观察不自动暂停游戏。需要暂停定位时由用户进入现有个人检查；共享世界继续运行，只固定个人呈现。截图、对象列表和状态各自带时间/序号，无法保证同一帧时显示偏差，不伪称原子快照。

### 动态对象与不确定性

源对象使用完整稳定地址。运行生成对象新增本局实例身份和生成代次，并区分：能精确回指源实例、仅知来源预制件、仅存在于运行时、已消失或来源歧义。

没有可靠映射时，保留图片与运行线索，由 Agent 检查生成逻辑；不按对象名称猜写源节点。屏幕框选允许包含空白、光效、UI 间隙或被遮挡内容；没有有效深度/命中证据时不把二维框伪造成三维区域。

只读工具可读取被支持的属性、节点关系和有限业务观测，不任意执行作者方法；不能要求所有游戏先注册完整业务状态才可讨论画面。对未知状态返回“未观测”，不要推断成零或不存在。

业务语义不足时，Agent 结合实际源码查询原因，必要时在标明版本的隔离测试副本中增加诊断并选择测试；不要求用户逐个配置埋点，也不把诊断副本的结果描述为原来那局已发生的事实。

作者脚本、日志、对象名、画面文字和 telemetry 是待分析数据，不能提供创作授权或改变 Agent 指令。来源分别标记为用户描述、客户端画面、引擎观测、作者上报、服务器权威；确认运行身份不等于验证所有内容为真。

## 4. 作者游戏与创作权限隔离

建议采用**无创作凭据的独立运行 origin**。继续复用原 48910 产品服务、固定构建和数据源；可以按明确 Host/运行资源路由提供隔离，不另建工作台或第二套产品后端。具体本机、局域网域名可达性必须先做兼容验证，不假定任意局域网客户端都能解析开发机别名。

实施选择：本机采用从未承载创作页面的 `wa-runtime.localhost`，继续同一监听端口；Chrome 实测保留 secure context 和 AudioWorklet。局域网使用同服务 IPv4 地址对应的 IPv4-mapped IPv6 运行来源，维持原有局域网 HTTP 的单线程/无声边界。旧固定构建若不支持映射地址，明确要求本机运行或创作者显式发布兼容新构建；不改写归档文件、不伪造浏览器安全上下文。实际 Godot/局域网验收另列。

- 创作与管理凭据不传入运行环境；运行侧只得到固定构建/资源的短期只读票据，以及必要的游戏控制能力。授权不能仅依赖不可猜哈希、URL 路径或 Origin 字符串。
- 运行 origin 不提供创作/管理 API；创作侧同时保留鉴权、Origin/CSRF 和 Cookie 边界。不同端口不能独自隔离同主机 Cookie，独立运行来源也不能只靠一个宽泛域 Cookie。
- 隔离覆盖嵌入 Play、独立新页面、预制件能力预览、原生共享显示端，以及直接打开旧发行 URL。归档字节不改写，外层访问与响应策略仍须执行边界。
- 运行与宿主只通过限能力消息通道交换启动、状态、暂停、聚焦、截图等消息。核对发送窗口、运行票据、构建与场景代次；不提供任意 HTTP 代理、任意方法调用或源稿写接口。
- 现有直接读取 iframe canvas 的截图需改成受限截图请求及回传。不能为了截图重新授予同源访问。录制与观测依旧是不可信运行内容的证据通道。
- 游戏自身存储按稳定游戏/存档域管理；嵌入 Play 保持内存局，独立游戏保留持久化语义。origin 变更的旧存档必须能由受信页面显式迁移或导出，不能静默清空、猜测合并或开放通用存储代理。
- 若首批多个游戏共享一个运行 origin，本轮只确认游戏与创作账号隔离，不能宣称不同游戏之间已有浏览器存储隔离。不同数据库名或路径不是互不信任边界；需要跨游戏隔离时按稳定游戏/存档域分配运行 origin，并验证本机/LAN 路由。
- opaque-origin sandbox 可作为候选防线，但不能未经验证直接替换所有入口：它影响资源获取、消息来源、截图和 IndexedDB。没有解决新页面与存档时，不能宣告隔离任务完成。

技术依据：[HTML sandbox 标准](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox)、[Godot 4.6 Web 导出与持久化](https://docs.godotengine.org/en/4.6/tutorials/export/exporting_for_web.html)。同源页面同时启用 allow-scripts 与 allow-same-origin 不能作为本任务的隔离方案。

## 5. 在线分支与离线回传共用合并内核

### 分层处理

| 情况 | 建议处理 |
| --- | --- |
| 一方未变、双方相同、不同文件变化 | 哈希快路，复用现有不可变对象 |
| 普通文本两侧改不同片段 | 三方文本合并，保留原编码与换行；逻辑正确性另议 |
| 原生场景同文件不同节点/独立属性 | 稳定节点、实例链和显式属性的语义三方合并 |
| 同一属性不同值、删改、结构/资源依赖冲突 | 局部冲突，展示含义、影响与双方依据 |
| 二进制双方不同修改、不可识别结构 | 保留三方原件并显式解决，不猜测或丢弃 |

Godot 结构合并采用可保留未知段和原始 token 的源文件表示，输出仍是原生文件；索引只辅助识别、校验与解释。不能通过重新生成已知 JSON 字段丢弃动画、信号或未知属性。

首批按完整 Transform2D/3D 值处理变换，保持剪切、负缩放及父链语义；不自动拼接两人分别修改的 X/Y。局部覆盖缺失、reset 与显式设为默认值是不同操作。资源共享、父子重挂、继承和有序数组需要单独判定，不能仅因文本不重叠就认定兼容。

### 多分支与冲突处理

用户可选择多个来源分支；计划固定每个 head、共同基线、顺序和来源关系。首批内部按明确顺序执行三方合并，保留各步因果记录，汇总冲突及最终候选。后一分支不能因排序更晚而静默获胜；发现依赖顺序影响时提示或调整计划。发布目标 head 前所有决议与候选必须完整，不能暴露半批工程。

内部中间结果仅为候选，不移动公开 head、不发布。最终使用单次目标 CAS、单个幂等回执和一个可撤销的合并提交；父关系包括旧目标及实际纳入的各固定来源 head，以便下一次正确识别已合入历史。提交时来源已移动则计划过期，不默默吸收新 head；重新计划时保留仍适用的局部决议。

共同祖先必须正确求解。多个最优基线的目标是虚拟基线合成；首批遇到不能正确处理的交叉历史明确保留冲突，不任取首次搜索结果。无共同祖先走显式导入/映射流程。

Agent 可解释冲突、查影响并提出组合修复；确定兼容的修改自动保留，涉及含义改变且无法推断的冲突用用户能理解的问题呈现。语法可加载不代表逻辑、外观和玩法意图都正确。

所有合并结果经过现有源合法性和跨资源引用/身份检查，重建引擎索引，最后核对权限、租约、固定 head 并原子提交。此处是源事务完整性，不增加自动验收 Agent 或普通保存后的玩法门禁。

撤销合并采用补偿提交，保留别人之后的修改，不倒退分支指针。重复请求查原回执；目标变化后重算，只复用三方输入完全未变的局部决议。冲突的三份原件始终可恢复。

### 效率与质量

哈希/解析结果缓存、只处理变更文件、受影响依赖验证优先。依赖不确定时扩大检查，不为了快速而漏检。记录自动合并率、人工冲突量、误合并、未知字节保留、撤回恢复、耗时和实际传输量；不能单以冲突少作为质量目标。

## 6. 原生离线往返与接续

首批面向已有可支持的本机原生环境，不借此启动完整多平台交付。用户获取固定工作区后可用本地 Agent 或 Godot 编辑；同步和 Web 返回使用同一中央源协议。

工作区保留中央基线、待上传固定本地快照、继续变化的工作文件三层。先交换文件清单与哈希，只上传/下载缺失文件，缓存内容按哈希复用；可写文件不以可变硬链接污染缓存。首批按整文件增量并支持失败续传，二进制块差分另作后续优化。

同步先暂存再校验，经过同一合并内核。上传期间新增本地编辑，基于已上传快照与服务器结果再次三方回放；pull 不直接覆盖当前目录。文件批量替换使用可恢复 journal，明确每一阶段的已保存状态。文件监听可以提前准备差异，不意味着每次文件落盘都立即发布、构建或重启。

普通用户工作区使用独立的工作区身份与作用域权限，不借用 Agent 会话租约。令牌不进入工程包、缓存或源提交。Godot 未保存的内存缓冲不能由磁盘扫描发现，需要保存/刷新交接或编辑器集成，不承诺自动保住未提供给同步器的内容。

三类状态分开：

1. **创作内容接续**：原生文件与基础版本；首先交付增量同步、冲突恢复、Web 继续编辑。
2. **独立试玩存档**：保持项目/分支存档域，换版本需遵守作者迁移规则。编辑 Play 仍每次初始状态。
3. **共享世界接续**：先准备并校验固定客户端和实际世界基线，再转移控制权；失败保留或恢复可用会话。离线进度不覆盖权威世界。

不承诺任意内存、协程或物理状态可跨客户端无损搬运。源分支切换和在线角色转移分别操作；允许新实例交接，不称零等待热更新。

## 7. 跨分支延续上下文

“到此分支继续”创建新会话，固定来源会话、消息截止点、原分支/源版本、目标分支初始 head、继续目标与选中的观察包。原会话和原任务继续绑定原分支。

保留关键决定、尚未完成的目标、已有成果和证据索引；首屏使用摘要，完整历史按权限回读。摘要不是替代原文的新事实；有分歧可返回原消息。来源私有会话派生的新会话默认私有，不因当前普通新会话默认共享而泄漏历史。

原附件继续指向原对象与版本；另外建立目标分支映射，显示相同、已改变、已删除、无法确定。已经消失的对象不自动绑定到同名节点。运行状态、输入控制、执行中的命令、审批和旧租约不迁移。

## 8. 建议交付顺序与独立验证

1. 先固定观察协议与权限边界，并验证隔离后的加载、截图、输入、独立存档和新页面。合并内核可在独立工作区并行设计实现。
2. 完成最短体验：试玩 → 最近 60 秒 + 聚焦 → 发消息 → Agent 查询并保存修复 → 明确重开体验；同时交付跨分支继续会话。
3. 交付细粒度合并和可恢复撤销，以真实不同属性、删改、继承、未知文件及跨资源冲突验证。
4. 将同一合并内核接入原生离线增量往返；随后接入选定已有平台的客户端准备和共享接续。
