# Three.js 工作台与双目标游戏

## 创作与发行

在原工作台新建空白游戏。Three.js 编辑器从当前固定源版本读取可投影的 3D 场景，协作者的选取、变换、撤销与 Agent 修改继续使用稳定的原生对象地址和源事务。Web 游戏从同一工程的 `web/main.js` 启动。编辑 Play 与「新页面游玩」固定同一构建。「导出 Godot 工程」和原生平台打包读取同一源版本的 Godot 场景与脚本。

在视口「更多」中点击「打开 Godot 对照窗口」，或复制同版本链接给有源稿读取权限的协作者。链接固定项目、分支、修订、打开的文档、主选对象和编辑相机。两边都能独立试玩。对照期间源稿视图只读，分支的新提交会显示更新提示。「回到当前源稿」重新读取最新版本并恢复编辑。公共玩家使用显式发行的构建。

Three.js 编辑和试玩都读取固定版本 `project.godot` 中的设计分辨率和拉伸设置。例如，1280×720 且保留宽高比的游戏会在窄视口上下留边，在宽视口左右留边。游戏画布、HUD 和指针共用中央的游戏区域。关闭拉伸或允许扩展的项目可以占满窗口。

已有项目可从「构建与导出 → 准备引擎迁移任务」打开当前分支的真实 Agent 会话，核对草稿后发送。迁移 Agent 读当前场景、预制件、公开属性及其有效实例值、素材和脚本，把目标端实现与现有定义一起提交。对齐玩法后按需构建并显式发布。新窗口的存档按分支保留，编辑试玩每局独立。迁移作者的具体 API 见[双目标制作说明](../skills/game-change/references/three-web.md)。

## 当前兼容范围

- Three.js 编辑器支持已投影的盒、球、柱、胶囊、环面、平面、标准材质和部分光照。保留有效世界矩阵、实例层级和对象地址。绘制按变化触发。对象与缩略图按需加载，重复几何和材质可共用。
- 主视口支持拾取、多选、移动/旋转/缩放、相机导航、用户与 Agent 的轮廓与标签、预制件放置和截图。复杂空间批注使用同一固定文档的 Godot 编辑器。对选择原生视觉派生的项目，额外支持固定原生网格、图像、静态骨骼姿势、多实例网格、Label3D、独立像素画布与 Control 手柄。两种描边都按可见网格集合合并所有者，并保留独立颜色带。已审核的 9 个 shader 按源码哈希匹配 Three.js 材质程序，其他 shader 只传安全的参数投影。
- Three.js 游戏可以使用自定义场景、UI 与行为。Web 构建读取固定源文件及锁定的 Three.js 依赖，在独立运行来源执行作者代码。旧 GDScript 游戏继续由 Godot Web 执行，完成 Web 入口迁移后再选择 Three.js。浏览器需要 WebGL 2。「指出这里」固定 WebGL 和游戏 HTML 界面合成后的画面。文本输入区域会遮盖，跨来源或私有嵌入内容不采集。同帧可见对象和控件的屏幕范围用于点选。[Three.js 渲染器说明](https://threejs.org/docs/pages/WebGLRenderer.html)
- 两个引擎分别实现游戏行为。资源目录、稳定 ID、有效属性和源文件由中央版本固定。自定义脚本、界面、材质、随机序列、音频和存档仍需按游戏比对。尚未验收全部效果的逐像素一致性。

## 编辑、暂停与运行观察

- 编辑 Control 后，Web 作者可通过 `bindProjectedControls` 把同一原生变换用于画布中的几何、HTML 控件和点击区域。《俄罗斯方块》的回归在临时中央库提交偏移、构建、运行并撤销。棋盘 x 从 0 到 100 再回到 0，开始按钮从 414 到 514 再回到 414。
- 在独立试玩时点「指出这里」可直接选当前画面。已进入暂停观察时也可点「指出暂停前画面」讨论先前的游戏 UI。该图保留自己的修订、关卡代次、时刻和屏幕范围。开启「显示游戏 UI」后，控件仍只读。共享世界仍采用个人呈现冻结。
- Web 编辑试玩会暂停宿主更新、游戏计时器和动画帧，并处理媒体、音频上下文和按住的输入。异步关卡逻辑可用 `createGame` 提供的 `signal` 和 `timers` 将延迟任务绑定到该局。独立 worker、外部服务和直接依赖墙上时间的作者代码有自己的生命周期。运行中的脚本故障可保留现场供观察后重开。
- 工作台提供两个目标的具名最高分转移。声明 `web/save-schema.json` 的工程可以在同一分支的新页游玩中显式采纳另一端的较高成绩。《俄罗斯方块》和《贪吃蛇》使用这个接口。任意进度、跨分支存档和在线世界状态需要各自的兼容规则。
- 回归入口包括 [双账号工作台旅程](../tests/creation/three-workbench-journeys.mjs)、[Control 修改与撤销](../tests/creation/three-control-binding.test.mjs)、[真实编辑器操作](../tests/creation/three-editor-actions.test.mjs)和[两端成绩转移](../tests/creation/three-score-transfer.test.mjs)。可用 `WA_THREE_TEST_CHROME` 指定本机 Chromium 后执行 `npm run test:three-parity`。其余八款的[源编辑双端检查](../tests/creation/three-default-edit-actions.mjs)使用独立工程。双账号工作台运行使用 48921，设置 `WA_PARITY_LIVE_AGENT=1` 会向隔离工程中的真实创作者 Agent 发送一次只读观察请求。

工作台按当前固定文档选择编辑器。「更多 → 当前视口」会说明切换或近似显示的原因。例如，含可见 Sprite2D、AnimatedSprite2D 或未投影原生几何的文档交给 Godot 拾取和编辑。包含已投影网格、同时使用粒子的场景仍可以在 Three 编辑器操作；当前视口会注明粒子需要在 Godot 窗口核对。未知着色器的材质参数近似以当前实际绘制的网格为准。

预制件面板里的动画、时间轴、技能和状态使用固定源的 Godot 能力测试场景。「用 Web 游戏核对」从同一源修订的正式游戏关卡在新页启动。关卡列表注明实例在源场景中摆放，或曾在这个版本的本窗口试玩中生成。尚未观察到的动态预制件也可以从游戏入口进入后触发。源修订或源稿读取权限改变时需要重新选择。

## 「贪吃蛇」实测

2026-11-02 的默认分发包包含移植后的「贪吃蛇」主干。原有 68 个文件逐一校验，全部保留，仅新增 `web/main.js`、`web/hud.js` 和 `web/rules.js`。已有安装保留自己的分支。Web ZIP 解压后用静态 HTTP 服务打开 `index.html`。Godot ZIP 解压后用 Godot 4.6 打开 `project.godot`。

真实 Three.js 与 Godot 游戏均通过开始、首次吃苹果、暂停/继续、切换视角、撞墙和重开。吃苹果后，两端都显示 10 分、6 节，重开后均为 0 分、5 节并保留最高分。Godot 工程自带的 20 项游戏检查通过。工作台里的内嵌 Play、新页启动、显式发布、同源 Godot 导出分别做了验证。

M5 Pro、无界面 Chrome 的单次主干编辑测试加载了 311 个节点、291 个网格。热刷新到固定源就绪约 1.05 秒。选中对象后持续移动相机约 2.4 秒，采到 144 帧，帧间隔 p95 为 16.7 毫秒。该数据覆盖这台机器和这一个场景。双用户选中已经浏览器验证。后续用真实活跃 Agent 对能量苹果采了七对连续帧，轮廓外接框相差约 1 像素。果肉内部和遮住果肉的叶片中心没有随描边闪动。相同主场景对照已校正默认取景、上下留黑和底色，地面明暗仍有差异。

2026-11-02 后续八个默认主干也已迁移。每款交付代码、用户内容和验证范围见[八个默认游戏迁移与对照](THREE-DEFAULT-GAMES.md)。
