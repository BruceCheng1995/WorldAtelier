# 私有管理后台

本次目标：在原 48910 服务中提供唯一管理员的运营与服务控制台。沿用工作台的暖白背景、深绿强调色、清晰边框和账号身份色。入口 `/admin`，在管理员自己的账号菜单增加「管理后台」。普通游戏拥有者仍只有游戏级权限。

## 页面与操作

| 页面 | 主要问题 | 内容与操作 |
| --- | --- | --- |
| 总览 | 当前是否健康，什么需要处理 | 实时资源摘要、连接/世界/任务计数、待处理问题、近期管理记录 |
| 服务器资源 | 谁占用了资源，何时发生压力 | CPU/内存/磁盘容量、已用、剩余并列比较；三类资源占用率同轴趋势；各资源总量/已用/剩余/本服务详细曲线，15 分钟/1 小时/24 小时、百分比/实际用量切换；目录用量、进程树、HTTP 与事件循环指标 |
| 账号与权限 | 谁能登录、创作和编辑游戏 | 搜索账号、修改账号名、禁用/恢复、撤销登录、允许/禁止新建游戏、按游戏授予编辑或只读/移除成员；管理员不可自禁用 |
| 游戏 | 管理全部游戏及访问范围 | 搜索、详情、成员、所有分支源版本与实际世界版本、公开试玩/仅成员、归档/恢复 |
| 资产 | 模型长什么样，什么在使用，能否停止使用 | GLB 交互预览、GDScript 目录、大小、来源、当前分支与历史引用、隔离/恢复；保留不可变文件 |
| 任务与审计 | 什么运行中，谁做过修改 | 开发/检查/构建的真实状态、世界状态；管理员操作时间、对象、理由、前后值和幂等回执 |

列表搜索、状态筛选和分页；详情用右侧抽屉保留列表位置。管理修改打开明确目标与影响的确认表单，必须填写原因；提交期间禁用重复操作。版本冲突要求刷新；网络回执不确定时复用同一请求 ID 查询/重试。空状态、首次采样、断线、权限失效均明确呈现。窄屏导航横向滚动，表格在独立容器中滚动。

## 身份与权限

- 单一 owner UUID 由服务器本地配置；不推断首个注册者，不从项目 owner、名称、浏览器字段授予平台权限。尚未绑定时默认无人有权访问。绑定不改动原账号密码。
- `/creation-api/admin/*` 每次读取与写入均验证当前持久身份。管理员网页和专有静态资源使用短期 HttpOnly、SameSite=Strict cookie 门禁；此 cookie 绑定原登录记录，退出/禁用/撤销登录立即失效。写入必须同源。
- 匿名访问 `/admin` 仅能看到登录门页，普通账号不获得页面内容或管理数据。工作台 bootstrap 仅给当前用户返回 `can_admin`，其他身份资料不包含平台授权。
- 后台展示运行任务的类型、状态、所属游戏和时间，不输出密码摘要、token、环境变量、进程命令行或私人会话正文。
- 禁用在共享权限层生效，覆盖 HTTP、WebSocket、资产授权、Agent 和后台任务；撤销原登录及资产授权，并断开现有连接。游戏归档禁止访问/新操作，断开玩家和编辑连接，保留源稿与世界检查点。已运行权威可保留无人运行，资源页继续如实展示；本版不提供清理或删除世界。
- 资产隔离阻止在线资产读取、重复上传和新引用，内置别名也受限；已经下载、加载或导出的副本不能远程收回。隔离前展示当前及历史引用，恢复不改变原哈希。

## 资产模型预览

资产列表的 GLB 行提供「预览模型」，在原详情抽屉内自动加载真实文件。拖动旋转、滚轮或双指缩放、右键平移；支持复位、线框、自动旋转、网格及放大预览。有动画时可选择、播放与暂停。键盘方向键旋转、加减键缩放、F 复位。显示实际加载的网格实例、三角面、材质、动画数量及包围盒尺寸；尺寸沿用模型单位，不推断所有文件均为米。

预览是只读文件检查，不修改资产、源稿或运行世界，不执行模型关联脚本。GDScript 明确提示没有 3D 模型。隔离资产不启动预览；已经打开的后台视口每 5 秒复核资产状态，隔离、权限失效或核对失败后停止显示。关闭详情、切换对象、锁定后台或离开页面取消请求并释放 WebGL 资源；隐藏页面暂停绘制。

`GET/HEAD /admin-models/:sha256.glb` 每次核对唯一管理员身份、文件状态、自含 GLB 结构和真实 SHA-256，返回 `private, no-store`，不生成项目权限或可转发的资产 cap。仅管理员可浏览非成员游戏的模型。纹理必须内嵌，浏览器只解析自身生成的 blob，不请求外部模型依赖。压缩扩展需要解码器时明确显示不支持，提供重新加载入口；缺失、损坏及图形上下文错误均不以空白成功替代。

渲染使用锁定版本的本地 Three.js，esbuild 按模型预览源文件更新时间生成内存 bundle，经管理员静态资源门禁提供，无 CDN、额外端口或单独构建步骤。这是后台资产查看器；创作工作台的 Godot 编辑/试玩流程继续使用原实现。

## 数据与监控口径

管理策略、审计与回执保存在原创作 SQLite。管理事务和审计原子提交，所有写入包含 `request_id`、`expected_version`、`reason`，版本不符拒绝。治理不修改不可变源稿、发行或历史验证结论。

主机指标由 Node OS 与文件系统实际采样；进程列表仅本服务和后代。HTTP 指标只统计该服务，不能称为全机网络速率。CPU 窗口、采样时间和历史起点在页面显示；无样本不补造曲线。高频样本内存保留一小时，每分钟持久化一个点，最多保留 24 小时。目录扫描异步、有数量与时间上限，失败或不完整要标记；磁盘容量指数据所在卷，与目录文件逻辑大小分开。

资源页的 CPU、内存、磁盘卡片使用一致的容量/已用/剩余结构，标出所选时段峰值与首末占用率变化（百分点）。单点或无有效记录不显示伪造的变化。组合图统一以各资源总容量为 100%，细分图可切到 CPU 等效逻辑核与内存/磁盘字节容量。数值容量的 KB/MB/GB/TB 使用 1024 进位。每张图可通过悬停、触摸或方向键读取真实采样点；自动刷新保留键盘焦点和被检查的时间点。

CPU 主机占用率已经按全部逻辑核归一；本服务原始 CPU 百分比以单核为 100%，在比较图按采样逻辑核数转换。新采样持久化核数，旧记录仅在明确说明下用当前核数换算。内存已用为 total−free，包含系统缓存，系统空闲不等于可回收后可用；一次采样只读取一次 free，并保持字节与占用率一致。磁盘 `free_bytes` 保留为兼容的用户可用空间（bavail），新增同义 `available_bytes` 和 `reserved_bytes`；图中明确区分已用、可用、预留，不将预留记成文件已用。本服务只指 Node 进程，子进程另列；服务目录扫描的逻辑字节数不能当作磁盘物理占用，也没有补造它的历史曲线。

## AI 用量与强制限制（2026-09-09）

同一后台 `#/ai` 列出全站与各账号今日启动次数、占用并发、执行器已报告 token 和单次时长上限。默认全站每日 500 次、并发 6、每日 1000 万 token；每账号每日 50 次、并发 2、每日 100 万 token；单次（包括持续 `/goal`）最多 60 分钟（1 小时）。全站与账号策略同时适用，管理员不豁免；可分别暂停 AI。每日统计按 UTC 00:00（北京时间 08:00）重置，持久化不因重启清零。

启动入口在同一 SQLite 事务内重新核对额度并写入运行；跨会话、分支共用账号限额，重复消息 ID 不重复计费，已经创建的失败运行仍计入启动次数。状态未知、取消尚未确认的执行占用并发，需通过原核对/清理流程释放。降低次数或并发只影响后续启动；暂停、token 超限或时长超限请求停止现有执行，并暂停原生 goal、撤销写入租约和清理命令。停止失败保留不确定状态，不以发送中断请求冒充已停止。单次时长每秒检查，token 上报时即时检查；审批不能恢复已因额度取消的任务，迟到的 goal 续轮继续中断。

计量使用本机 Codex App Server `thread/tokenUsage/updated` 的累计高水位增量，重复/乱序通知不重复累加。首次接手旧线程仅记录本次 last 报告，不补算旧历史；跨日按收到增量的时间归属。token 是执行器报告的总量（含缓存输入），不等于货币费用或供应商账单；没有报告显示“暂无报告”，不能视为零用量。事件上报和执行器停止存在延迟，因此 token 阈值不是供应商端精确硬封顶；无报告时次数、并发、时长仍生效。本功能控制此服务管理的创作执行，不能计量其他程序直接调用供应商的费用。

策略修改沿用管理员门禁、同源检查、必填原因、版本冲突和幂等审计；只改策略与用量记录，不改源稿、发行或历史验证。`tests/creation/ai-limits.test.mjs` 用临时 SQLite 与模拟执行器验证边界，真实后台表单另在临时服务上操作；这些测试不代表已消耗真实付费 token 验证停止。

### 总览 token 信息（2026-09-09）

`#/overview` 顶部直接读取现有 `GET /creation-api/admin/ai/global`，与限额页共用持久用量和策略，无需后端重启。展示今日已报告总 token、每日上限、占比、按报告计算的剩余额度、用量报告次数，以及当前并发、今日启动、单次时长和今日触发限额次数；超过额度时额外展示超出量。

达到 80% 标记“接近上限”，达到或超过 100% 标记“已达上限”。启动状态同时解释全站暂停、token 达限、启动次数达限、并发已满；全站允许启动不代表各账号限额也满足。没有报告时总量显示“暂无报告”、剩余显示“—”，不绘制零用量进度。AI 请求失败时仅该区域显示暂不可用，其余总览继续读取；鉴权失败仍锁定整个后台。沿用 5 秒刷新，保留用量入口的键盘焦点。每日重置时间和执行器报告边界在卡片中明确标注。

## 账号改名（2026-09-10）

所有已登录用户均可从工作台右上角账号菜单选择「修改账号名」。名称与登录名同步更新，原密码及现有登录继续有效；用户 ID、成员权限、长期会话和按 UUID 生成的身份色保留。名称沿用 1–160 字符限制，去除首尾空白，以 NFKC 和小写规范化检查唯一性，并拒绝控制及隐藏字符。历史审计名称保留当时快照。

自助接口为 `PATCH /creation-api/auth/profile`，请求 `{name, expected_name}`，仅允许修改当前认证账号，返回 `{user}`。旧名称冲突返回 409，同时递增账号管理版本，避免覆盖后台并发修改。

后台「账号与权限 → 管理账号 → 修改账号名」沿用管理确认表单、必填原因、版本校验与幂等审计；`PATCH /creation-api/admin/users/:id` 使用 `action: "rename"`、`value: 新名称`。管理员本人也可改名。名称变化经 `user_updated` 和协作 presence 同步到本人及可访问同项目的在线窗口；断线重连从当前持久身份恢复名称。

验证：`node --test tests/creation/account-rename.test.mjs` 在独立临时 SQLite、HTTP 与 WebSocket 上 7/7 通过，覆盖改名后的登录、权限与会话连续性、NFKC 唯一性、输入校验、同源与越权拒绝、并发冲突、后台审计及重启持久化。`branch-presence.test.mjs`、`branch-presence-client.test.mjs`、`topbar.test.mjs` 回归 18/18 通过。Chrome 隔离工作台实际验证普通用户入口、改名成功、重名错误及修正后保存，身份色保持一致。

正式复验：在当前创作执行和构建均结束后，通过原受保护启动器更新 48910；后台实际保存 Bruce1 → Coconut，数据库与审计回读一致，原账号 ID 和有效登录保持不变。正式工作台已显示 Coconut，账号菜单提供「修改账号名」。

## 资源市场运营与资产占用（2026-09-10）

后台新增 `#/market`，与已有资产隔离页分别管理资源包和模型/脚本文件。资源市场支持搜索、上下架筛选、按热度/下载量/包体积/更新时间/名称排序及分页；抽屉展示来源、许可、固定内容版本、计数与历史原件用量。上下架沿用唯一管理员、同源写入、原因、治理版本和幂等审计。内容更新递增治理版本防止陈旧操作；服务重启、官方重装和新版安装均保留管理员下架状态。

下架立即关闭市场发现、公开详情（包含固定旧版本）、原件文件和新导入。已经导入游戏的独立副本与已下载文件继续保留，下架不删除文件、不改变游戏源稿/构建/发行。在下架前已经进入中央异步提交的导入按既有事务完成。

- 累计下载：人或 Agent 成功将完整资源包导入游戏的次数，共用 `importToProject`。以中央 `creator_receipt` 的准确请求指纹为依据，同一事务重试只计一次。提交前保留小型计量意图，计数及去重记录原子保存；进程在源提交后中断，重启依据匹配回执补记。失败及无回执不计，不推断上线前历史。
- 单文件下载：文件清单的显式 `?download=1` GET，服务端发送完成后计数，HEAD、普通预览文件读取不计。该指标独立于整包下载；不代表接收端已保存成功。
- 浏览：成功的公开详情 GET 请求次数，含重复浏览及 HTTP 客户端，不是独立访客。列表、图片、模型预览、后台查看和 Agent 内部详情工具不计。
- 近 7 日：UTC 当天及此前 6 个自然日，北京时间 08:00 换日。热度 = 浏览数 + 5 × 成功导入数。累计值与最近 7 日分桶保存在原 SQLite；页面注明首次计数时间，重启不清零。

`GET /creation-api/admin/market` 返回分页资源及全市场摘要、占用快照；`GET /creation-api/admin/market/:id` 返回抽屉数据；`PATCH` 接收 `{request_id,expected_version,reason,status:'listed'|'unlisted'}`。`version` 为治理整数，`asset_version` 为不可变内容 hash。

资产扫描至多每分钟一次、仅在管理读取时触发；每轮总计限 6 秒 / 100,000 条目，不跟随符号链接。展示市场目录、游戏原生源对象、模型与脚本目录的逻辑字节与文件系统分配块（512 × stat.blocks），分配块按 inode 去重。市场对象另按内容 hash 分成当前版本、仅历史版本引用、未被版本引用（包括未发布上传），并检测缺失原件。单包显示全部保留版本的对象用量；多个资源包可共享原件，单包用量不能直接相加。扫描未完成、分配块不支持或卷信息不可用明确显示，容量 80%/90% 显示提示。分配块不等于克隆/压缩文件可释放的独占空间；不提供自动删除。派生工程、工作区及构建等额外副本在服务器资源页的服务目录用量中查看。

新独立测试：`node --test tests/creation/admin-market.test.mjs`（临时 SQLite、HTTP、真实文件统计；回执计量边界 fixture，无 Godot）；`node tests/creation/admin-market-browser.mjs`（隔离端口与 Chrome headless，实际搜索、排序、上下架、审计及小屏界面）。上线状态与本轮记录见 `docs/ADMIN-MARKET-VERIFICATION.md`。
