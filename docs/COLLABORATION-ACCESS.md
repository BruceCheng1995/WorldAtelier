# 游戏协作与权限

2026-09-08。实现于现有 48910 工作台，不另建协作后台。权限属于游戏，覆盖其主干与所有分支；源稿、可玩发行和运行世界仍各自保存。

## 角色与入口

| 身份 | 浏览场景、预制件与试玩 | 修改源稿、运行创作 Agent | 查看会话 | 管理成员、审批与邀请 |
| --- | --- | --- | --- | --- |
| 注册试玩者 | 可以，正式服务默认开放 | 不可以，可申请编辑 | 不可查看项目会话 | 不可以 |
| 只读成员 | 可以 | 不可以，可申请编辑 | 自己的历史会话及明确共享的会话 | 不可以 |
| 编辑成员 | 可以 | 可以 | 自己的会话及明确共享的会话 | 不可以 |
| 拥有者 | 可以 | 可以 | 自己的会话及明确共享的会话 | 可以；拥有者不可被降级或移除 |

拥有者身份也不赋予读取其他人私人聊天的权限。游戏编辑权不改变现有 Agent 执行权限选择协议；本机 full-access 仍是可信协作者的显式执行选择，不是多租户安全沙箱。游玩控制属于当前玩家，编辑权限变化不停止其他玩家或整个世界。

游戏详情和工作台顶栏常驻蓝色「分享」入口，保留感叹号提示只读、申请等待、拥有者待审批和异常。所有入口进入同一个紧凑 Share 弹窗：邀请用户名、待审批申请、访问范围、已受邀成员和复制链接；申请详情、一次性邀请与共享记录为次级页面。视口不堆叠权限条。权限变化不要求退出账号或重新加入游戏。

## Figma Share 需求映射与界面（2026-09-08）

本轮查看了 Figma 官方 [Share files and prototypes](https://help.figma.com/hc/en-us/articles/360040531773-Share-files-and-prototypes) 的现行布局截图及 [Request to edit](https://help.figma.com/hc/en-us/articles/4408435431319-Request-to-edit-a-file) 流程。既有产品的实际编辑账号弹窗截图位于 `.local/share-redesign/01-before.png`：原 760 px 管理面板将成员、申请、邀请分散为栏目，缺少普通分享链接；每个成员占独立大卡片。改版以原工作台和官方 Share 截图为视觉目标，采用 520 px 白色弹窗、12–14 px 文字、蓝色主操作、紧凑成员行，内容自适应高度，长列表内部滚动。

| Share 需求 | 本产品实现 | 保留的业务边界 |
| --- | --- | --- |
| 顶栏 Share | 「分享」按钮及感叹号，所有入口指向同一主弹窗 | 不增加视口提示条 |
| 按人邀请 | 输入注册用户名，支持逗号分隔的最多 10 人；选可查看或可编辑 | 当前账号没有邮箱身份，明确使用用户名及站内通知，不假装发送邮件 |
| 谁可以访问 | 拥有者可选择任何已注册用户或只有受邀成员 | 新旧游戏默认保持既有公共只读；服务器关闭公共试玩时不能由游戏设置绕过 |
| 每个人可以做什么 | 成员行内下拉直接改权限；降级、移除先明确影响 | 只有拥有者管理；不能移除拥有者，不开放公共编辑 |
| 权限申请 | 只读用户在分享主页发起申请；拥有者主页直接批准或拒绝 | 拒绝、撤回、再次申请、说明、结果通知、旧回执保护保留 |
| Copy link | 常驻复制普通链接；保留当前游戏和当前分支 | 不复制登录状态、邀请码或临时参数；链接本身不授予编辑权 |
| 局域网复制 | 本机打开时优先使用服务器报告的局域网地址，局域网打开时保持当前来源 | 网络与端口未做外部部署；剪贴板不可用时选中文本供手动复制 |
| 更多共享方式 | 「邀请链接」提供现有 24 小时一次性邀请码及撤销 | 与普通查看链接区分；未注册同事先注册再确认加入 |
| 记录和通知 | 共享记录为次级入口，申请和邀请投递真实 Inbox | 共享权限不公开私人 Agent 会话 |

普通链接的访问规则由服务端每次检查。访问范围是 `creator_project.public_play` 的项目覆盖，和私有管理后台使用同一字段、同一个 `permission_version`。从公共改为仅受邀者后，未受邀用户失去 HTTP 与 WebSocket 访问，显式成员仍保留各自权限。复制链接到另一个分支不改变整个游戏的权限范围。

直接邀请先校验整批用户名及状态，再原子提交成员、待处理申请结束状态和 Inbox outbox；重复用户名规范化去重，重复邀请不降低既有权限。新邀请和范围修改都要求当前权限版本及幂等请求 ID。停用账号不能获得新授权；停用拥有者发出的旧邀请码不能继续授权。

API：`POST /creation-api/projects/:p/share-invitations` 接收 `names[]`、`role`、`expected_version`、`request_id`；`PATCH /creation-api/projects/:p/sharing` 接收 `general_access`、`expected_version`、`request_id`。`GET .../collaboration` 返回 `share_version`、`share_urls`、`public_access_available` 与能力字段，旧服务不显示尚未提供的写操作。

## 申请闭环

1. 用户提交可选的 500 字以内说明；服务端固定真实申请人和游戏。每人每游戏仅保留一条待处理申请，重复点击和网络重试不会重复通知。
2. 拥有者收到持久化消息和待处理角标；在消息中点击「处理申请」直接进入对应游戏的申请页。读过消息不会批准申请。
3. 拥有者批准或拒绝，可附处理说明。批准与成员角色、申请状态、活动记录原子提交；申请人收到结果，并实时获得编辑入口。
4. 等待中可撤回。拒绝、撤回后可再次申请；旧申请保留结果，旧批准回执重放不能在撤权后重新授予权限。直接管理成员或通过邀请开通编辑也会结束重复的待处理申请。
5. 申请页支持空状态、加载、失败重试、并发处理冲突和失效状态。权限和版本由服务端决定，页面不靠缓存作授权判断。

## 成员和邀请

拥有者可以把成员切换为只读或可编辑，也可以移除成员。操作前明确说明影响；正式公共试玩模式下，移除成员后仍能以注册试玩者身份浏览和游玩。操作即时通知受影响用户，并保留是谁在何时修改了谁的权限。

邀请必须选择只读或可编辑，有效期 24 小时，一次使用，可撤销。加入前先登录并明确确认。列表不显示邀请码；生成后提供链接和代码，LAN HTTP 无剪贴板权限时提供选中后手动复制的回退。角色更高的人使用低权限邀请不会被降级。已使用邀请不会再次授权，权限被降级或移除后，此前生成的未使用邀请码也不能绕过该变更；拥有者新建的邀请可以再次授权。

## 同步、隐私和可靠性

- 写入接口仍在每次操作时校验当前权限。全局 WebSocket 权限消息覆盖游戏库页面、场景和会话订阅；断线重连重新读取当前权限。
- 降级立即停止编辑手柄和未提交的场景操作；私人会话订阅失去访问权时清除。未提交聊天草稿保留在当前窗口，不自动发送；公共试玩保持原有世界会话。
- Agent 撤权立刻废除写入租约；启动回执延迟到达时按实际执行编号中断并使用既有命令清理协议。未知执行结果保持待核对，不能伪造取消成功。
- Inbox 新增专用协作事件来源，只投递实际申请人、受影响成员和拥有者。只读用户能看到自己的结果，但不会因此读取其他人的通知、Agent 正文或问题证据。
- 申请、成员、审计和待投递通知在同一 SQLite 事务提交。通知以持久化 outbox 幂等写入 Inbox，读取或重启时重试；通知失败不能让已批准的权限变化被误认为未提交。
- 所有新写入口使用请求 ID 保留幂等回执。申请处理使用申请版本，成员修改使用游戏权限版本；旧的 role-only 成员接口继续兼容，但新界面一律携带版本。
