2. 外部端可以编辑场景、离线制作内容，也可以下载主干或指定分支的最新可运行版本和对应状态。
3. 下载后能进入目标世界查看、验证或继续游玩；网页端也需要真实玩法体验。
4. 从头建立新工程；旧 `RuntimeAtelier` 和 `runtime-atelier` 两个工程可以直接删除。新工程名采用“世界工坊 · World Atelier”，路径为 `/Users/chengzhi/Projects/WorldAtelier`。

用户主动切分支或升级客户端时，可以准备并打开匹配的新运行实例，再接续目标世界。此前对普通内容更新的无重启要求继续适用于兼容的现场热更新，不能被扩大为“所有跨分支跳转必须保持同一进程”。

## 本轮的设计选择

- 中央服务管理控制与持久化事实；每个在线世界有一个带代次的权威写者，Godot 负责目标玩法运行。
- 源码最新、可玩最新、运行房间状态各有独立身份；一个分支可有多个进度不同的世界。
- 下载主干/分支时先解析并锁定完整发行清单；状态接入再核对目标房间的实际版本。
- 离线创作内容使用三方合并；离线试玩结果作为独立状态分支，不能自动覆盖主干的背包、任务或在线世界。
- 跨分支保留账号与界面偏好；玩家进度默认按目标世界/存档域管理，额外继承规则必须明确。
- 前端产品流程从“项目 → 分支 → 版本 → 世界 → 编辑/游玩”展开，中央目录和下载/进入协议先于大量玩法制作。

## 建议实现顺序

先实现一个本地中央服务的工程/分支/可玩版本目录和不可变产物；接一个最小 Godot 世界的检查点与下载进入；然后验证离线分支上传、主动跳转与控制权交接；让网页端从同一入口进入真实玩法；最后扩大多人、模块热更新、依赖组与资源调度能力。每一步都需要真实执行和故障验证，不能用静态页面冒充运行系统。
