# 构建与协作编辑隔离

2026-09-09：原生工程的 Play、原生编辑视口、源码包和应用导出在独立 Node 子进程执行。原有单任务队列和最多 12 个活动任务的限制保留；没有另起产品服务或协作端口。

受理时检查权限并固定已提交的 `source_revision`、入口、运行框架、存储身份和工具链。每个任务使用 `builds/<job id>/` 下的独立工程。之后分支可以继续提交；执行器只读取任务绑定的旧版本，不读取移动 head 作为构建内容。完成构建不发布游戏、不移动分支、不改变其他浏览器的试玩状态。点击时尚未提交到服务器的本地编辑不属于这个快照。

主服务保留授权、排队、持久化进度和产物入口。执行器不运行 CreationService/CreationBuilds 构造器，不启动 Agent 或世界，不执行数据库迁移或全局任务恢复。它用只读 SQLite 连接逐次查询当前权限，避免长事务；所有任务状态通过 IPC 交回主服务保存。主服务合并后来加入的有效请求者，并在接受成功结果前再次检查权限。

原生工程物化、源文件校验、Godot 引擎复制、运行检查、导出、Web 适配和压缩校验均在执行器中。执行器尽可能使用较低 CPU 调度优先级。执行器崩溃、权限失效或服务关闭不能报告成功；关闭时清理其 Godot 进程组，超时强制结束执行器。Godot 原有受限执行环境及固定输入校验保留。

这不等于零耗时或硬件资源完全隔离。受理前固定框架、计算首次工具链身份和查找可复用产物仍有短时主线程工作；同机 CPU、磁盘和内存仍共享。旧格式兼容任务暂保留原执行路径。首次构建仍可能排队，当前窗口进入 Play 时也仍需等待运行包；其他编辑者不需要等待这个任务完成。
