## 基线、交付与集成

1. 协调者将 Git 可见的源码、项目自有资产及文档封装为只读快照，附 SHA-256 清单。排除 `.local`、数据库、凭据、依赖目录、引擎下载源码和构建输出。快照不是经过验收的发行。
2. 新任务核对自身路径为分配的 worktree，在该目录导入快照、逐项核对哈希并建立本地基线提交。禁止复制根目录 `.git`、凭据或运行状态，禁止将快照基线提交整体合回主工程。
3. A 先提交稳定对象寻址、父子变换、预制件版本 / 覆盖的契约和迁移范围；B 的验收记录引用不透明对象 / 版本身份，不自创第二套资源 schema。主集成确认契约后，才能进入依赖此契约的阶段。
4. 每个任务交付可审查的小提交或基于该快照的精确差异，并提供 `docs/handoffs/<task>-HANDOFF.md`：基线、改动文件、契约、前提、用户 Case、实际验证、已知失败、主集成接入步骤。自行提交只发生在自己 worktree；绝不直接合并、发布或更新主运行世界。
5. 主集成先保护现有未提交工作，再逐批应用差异；检查基线到当前的差异，解决冲突，不能覆盖其他任务新修改。公共入口、数据库迁移与世界应用均串行。
6. 独立测试者对合入后的固定源码 / 构建验证；通过后主集成发后续任务，复用空闲开发任务推进个人检查与跨端。前置未满足时开发任务报告具体依赖与已完成成果，不用猜测基线继续写，也不把等待当完成。
